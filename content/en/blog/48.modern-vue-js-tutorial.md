Learning a modern **Vue.js tutorial** means understanding how declarative interfaces work using the **Composition API**, automatic reactivity systems, and Single File Component (`.vue`) architecture. Created by Evan You, this progressive JavaScript framework helps you build interactive interfaces, from small isolated components to large-scale single-page applications, offering a friendly learning curve and high performance.

Many beginner programmers get stuck learning outdated materials that still use the Options API, Vue CLI, or Vuex. However, current industry standards have fully shifted to the Vue 3.5+ ecosystem, which relies on Vite as a build tool and Pinia for state management. This guide breaks down the foundations of Vue using the latest best practices so your code stays clean, easy to test, and ready for production environments.

## Why Learn Vue.js in the Current Frontend Ecosystem?

Vue is designed as an incrementally adoptable framework. You can drop it into a simple HTML page to replace manual DOM manipulation, or use it as the foundation for enterprise-scale web applications. This adaptability places Vue in the top three global frontend frameworks alongside React and Angular, backed by an active worldwide community.

Dario Benevento explains in his book *Frontend Development (UIUX & Psychology)* that Vue rests on two main pillars: declarative templates and component composition. The declarative approach frees developers from the hassle of imperatively selecting elements using `document.querySelector`. You simply define the application state, and Vue automatically updates the DOM whenever that state changes.

The performance leap in the **Vue 3.5 (Tengen Toppa Gurren Lagann)** release further solidifies its position. Overhauling the internal reactivity system with a doubly-linked list structure successfully cut memory consumption by up to 56% and sped up reactive array operations by up to 10 times without breaking existing API compatibility. The Vue core team is also finalizing **Vapor Mode** for the upcoming Vue 3.6 release. This optional compilation strategy drops the Virtual DOM (opt-in via `<script setup vapor>`) and translates components directly into pure DOM instructions for heavy-load pages.

For those just starting a career as a [modern web developer](/blog/what-is-a-web-developer-guide), mastering Vue provides a solid footing before moving on to full-stack frameworks like [Nuxt.js for SSR and SSG needs](/blog/introduction-to-nuxt-js-vue-framework-ssr-ssg).

## Core Paradigm: Single File Components and the Composition API

Before writing your first line of code, you need to understand Vue's primary working container called the **Single File Component (SFC)**. A single `.vue` file encapsulates three interface layers at once in a neat module:

![Visual diagram of a three-tier web component structure with interconnected data flows](/article/tech-vue-js-tutorial-ilustrasi.webp)

1. **`<template>`**: Contains the declarative HTML markup structure where data renders.
2. **`<script setup>`**: The place to write JavaScript or TypeScript logic, define reactive state, and manage the component lifecycle.
3. **`<style scoped>`**: Contains CSS rules isolated specifically for that component so they do not break the visual styles of other components.

Since the arrival of Vue 3, the official community established the **Composition API** (specifically with the `<script setup>` attribute) as the primary standard, replacing the Options API from the Vue 2 era.

| Comparison Aspect | Composition API (`<script setup>`) | Options API (Old Vue 2 Standard) |
| :--- | :--- | :--- |
| **Code Organization** | Grouped by feature or logical function | Split into `data`, `methods`, and `computed` blocks |
| **Context Dependency** | Context-free, does not use `this` | Highly dependent on the `this` runtime context |
| **Logic Reusability** | Easy to extract into Composable functions | Uses Mixins which are prone to naming collisions |
| **TypeScript Support** | Natural and accurate type inference without friction | Requires complex additional type wrappers |
| **Production Bundle Size** | Friendly to tree-shaking and code minification | Option object properties are hard for bundlers to compress |

Michael Thiessen highlights in his book *Vue Tips Collection (Second Edition)* the main reason why the Composition API is so revolutionary: it is **context-free**. In the Options API, developers often attach global properties to the component context, tying the logic tightly to the `this` object and making it hard to separate into external files. Without the `this` binding, every reactive function in the Composition API works like a regular JavaScript function that is easy to move, unit test independently, or even run inline within a single component.

## Vue.js Tutorial: Practical Steps to Build Your First Component

We will immediately create a new project and assemble our first interactive component using modern standard tools.

::steps
### Initialize the Project with Vite

Vue CLI is officially in maintenance mode. Now we use `create-vue`, the official **Vite** based tool that instantly starts an ES modules based development server. Open your terminal and run the following command:

```bash
npm create vue@latest
```

The terminal will display several configuration questions. For the basic learning stage, name your project, select **Yes** for the TypeScript option (optional, but highly recommended), Pinia, and Vue Router as needed, then continue installing the packages:

```bash
cd your-project-name
npm install
npm run dev
```

### Understanding Basic Reactivity (`ref` and `computed`)

Open the project in your code editor, then notice how Vue manages data changes. We use the `ref()` function to wrap primitive values or objects to make them reactive, and `computed()` to generate derived values that automatically recalculate when their source data changes.

Create or modify the `src/components/UserProfileCard.vue` file with the following code:

```vue
<template>
  <section class="profile-card">
    <h2>Hello, {{ formattedHandle }}</h2>
    <p>Account Status: <strong>{{ statusLabel }}</strong></p>

    <div class="form-group">
      <label for="username-input">Change Username:</label>
      <input
        id="username-input"
        v-model.trim="username"
        type="text"
        placeholder="Type username..."
      />
    </div>

    <button type="button" @click="toggleStatus">
      Toggle Online Status
    </button>
  </section>
</template>

<script setup lang="ts">
import { ref, computed } from 'vue'

// 1. Reactive state using ref
const username = ref('dinarpermadi')
const isOnline = ref(true)

// 2. Computed property: auto-updates when username or isOnline changes
const formattedHandle = computed(() => `@${username.value.toLowerCase()}`)
const statusLabel = computed(() => (isOnline.value ? 'Active' : 'Offline'))

// 3. Standard state mutation function
function toggleStatus() {
  isOnline.value = !isOnline.value
}
</script>

<style scoped>
.profile-card {
  padding: 1.5rem;
  border: 1px solid #cbd5e1;
  border-radius: 0.5rem;
  max-width: 400px;
}
.form-group {
  margin: 1rem 0;
  display: flex;
  flex-direction: column;
  gap: 0.5rem;
}
</style>
```

Notice the `v-model.trim="username"` directive on the `<input>` element. This directive creates two-way data binding and automatically trims whitespace at the beginning and end of the text. As the user types, the `username` variable updates instantly, and `formattedHandle` changes right along with it.

### Component Communication with Props and Emits

Real applications consist of many components exchanging data with each other. The parent component sends data to the child component via **Props**, while the child component sends event signals back to the parent via **Emits**.

Since Vue 3.5, the **Reactive Props Destructure** feature has become fully stable. You can directly destructure `defineProps` and provide default values using pure JavaScript syntax without losing reactivity:

```vue
<script setup lang="ts">
// Reactive props destructuring (Stable in Vue 3.5+)
const { title = 'Default Title', initialCount = 0 } = defineProps<{
  title?: string
  initialCount?: number
}>()

// Define events that can be sent to the parent component
const emit = defineEmits<{
  updateCount: [newValue: number]
}>()

function notifyParent() {
  emit('updateCount', initialCount + 1)
}
</script>

<template>
  <div class="counter-box">
    <h3>{{ title }}</h3>
    <p>Initial value from parent: {{ initialCount }}</p>
    <button type="button" @click="notifyParent">Add & Report to Parent</button>
  </div>
</template>
```

### Extracting Logic into a Composable

When several different components start needing the same reactive logic, do not copy and paste the code. Extract that logic into the `src/composables/` folder.

```ts
// src/composables/useCounter.ts
import { ref, computed } from 'vue'

export function useCounter(initialValue = 0) {
  const count = ref(initialValue)
  const doubleCount = computed(() => count.value * 2)

  function increment() {
    count.value++
  }

  function decrement() {
    count.value--
  }

  return {
    count,
    doubleCount,
    increment,
    decrement
  }
}
```

Now, any component simply needs to call `const { count, increment } = useCounter(10)` inside `<script setup>` to get a complete and isolated counter function.

## Clean Code Architecture: Separating `composables` and `utils`

One sign of a mature frontend engineer lies in their ability to maintain folder architecture boundaries. As a project grows, many beginner developers mix standard helper functions with Vue reactive functions in the same folder.

Michael Thiessen emphasizes in his book *Nuxt Tips Collection* the importance of separating discipline between the **`utils`** and **`composables`** folders:

* **The `utils/` Folder (Pure Functions)**: Must only contain pure algorithmic functions that are deterministic, lacking reactive state or component lifecycles. Examples include currency formatters, date calculators, or email validators. Given the same input, these functions always return the same output without side effects.
* **The `composables/` Folder (Stateful Logic)**: Contains functions that use Vue's reactivity APIs (`ref`, `computed`, `watch`) or lifecycle hooks (`onMounted`, `onUnmounted`). Their names must begin with the verb `use`, such as `useCounter`, `useFetchUser`, or `useDarkMode`.

::tip
If a function does not import anything from the `'vue'` package, it is almost certainly a pure utility and belongs in the `utils/` folder, not `composables/`.
::

## Backend Integration: Why is the Vue.js and Laravel Duo So Popular?

Many backend developers search for a **Vue.js Laravel tutorial** because these two technologies share a very close partnership history in the web development industry. Laravel has included first-class support for Vue for a long time, but integrating them is much simpler now than it was a few years ago.

Previously, developers had to build two separate repositories: Laravel as a REST API with complex JWT token authentication, and Vue as a separate SPA that called endpoints via Axios. That approach was often too heavy for small to medium-sized teams.

In today's Laravel 11+ ecosystem, the dominant standard pattern is the combination of **Laravel + Inertia.js + Vue 3**. Inertia acts as a bridge that allows you to build a modern monolithic application with an SPA feel:

1. **No Separate API**: You still write standard routing and controllers in Laravel.
2. **Direct Data Delivery**: Instead of returning a traditional Blade view, the Laravel controller renders the Vue component directly and injects data as properties.
3. **Fully Reactive Interface**: Data from the controller arrives as `props` inside the `.vue` component file. Pages transition instantly on the client side without full page reloads and without the hassle of managing separate API tokens.

If you work in a pure JavaScript ecosystem without PHP, Nuxt handles a similar role very neatly alongside ready-to-use components from [Nuxt UI to build modern interfaces](/blog/nuxt-ui-modern-design-guide).

## 5 Common Beginner Mistakes in Vue 3 and How to Avoid Them

Understanding the basic syntax is only half the journey. The other half is recognizing reactivity traps that often cause applications to fail to update the display or suffer from memory leaks.

### 1. Forgetting to Write `.value` Inside the Script Block

Inside the `<template>`, Vue automatically unwraps reactive values (auto-unwrapping) so you simply write `{{ count }}`. However, inside the `<script setup>` block, a `ref` variable is a wrapper object. Writing `count++` directly will not work; you must access it through the property like `count.value++`.

### 2. Breaking `reactive()` Reactivity During Destructuring

Unlike `defineProps` in Vue 3.5+ which is specially compiled, directly destructuring a standard `reactive()` object breaks its reactive proxy connection:

```ts
import { reactive, toRefs } from 'vue'

const user = reactive({ name: 'Andi', age: 20 })

// WRONG: name and age variables lose reactivity
const { name, age } = user

// RIGHT: use the toRefs helper to keep them reactive
const { name: reactiveName, age: reactiveAge } = toRefs(user)
```

Because of this trap, the modern community recommends using `ref()` as the primary standard for all data types.

### 3. Ignoring Watcher and Event Listener Cleanup

When you set up an interval timer, a WebSocket subscription, or a manual DOM event listener inside a `watch` or `onMounted`, make sure to clean up those side effects when the watcher updates or the component is destroyed. In Vue 3.5+, use the built-in `onWatcherCleanup()` function or the `onUnmounted` lifecycle:

```ts
import { ref, watch, onWatcherCleanup } from 'vue'

const searchQuery = ref('')

watch(searchQuery, (newQuery) => {
  const controller = new AbortController()
  fetch(`/api/search?q=${newQuery}`, { signal: controller.signal })

  // Cancel the previous request if the user types again before it finishes
  onWatcherCleanup(() => {
    controller.abort()
  })
})
```

### 4. Accessing DOM Elements with `document.querySelector`

Do not grab HTML elements using manual DOM selectors inside a Vue component. Use the `useTemplateRef()` feature, introduced stably in Vue 3.5, to bind element references safely and in isolation:

```vue
<script setup lang="ts">
import { useTemplateRef, onMounted } from 'vue'

const inputElement = useTemplateRef<HTMLInputElement>('search-input')

onMounted(() => {
  inputElement.value?.focus()
})
</script>

<template>
  <input ref="search-input" type="text" />
</template>
```

### 5. Forcing Re-renders with `$forceUpdate`

When the DOM display does not change as expected, beginners are often tempted to call `$forceUpdate()`. Michael Thiessen reminds us in *Vue Tips Collection (Second Edition)* that forcing a render almost always indicates a mistake in your reactive data mutations.

::warning
If you absolutely need to reset a third-party component's lifecycle from scratch, do not use `$forceUpdate`. Use the **Key-Changing Technique**: assign a `:key="uniqueKey"` attribute to the component, then change the value of the `uniqueKey` variable. Vue will cleanly destroy the old instance and mount a new instance from the beginning.
::
