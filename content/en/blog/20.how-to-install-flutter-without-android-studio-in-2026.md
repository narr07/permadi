You can install Flutter without Android Studio. Flutter needs only three things to build Android apps: the Flutter SDK, a JDK, and an Android SDK installed through the command-line tools. You write code in VS Code. The command-line tools package is about 156 MB, while the Android Studio installer is 1.5 GB.

![Installing Flutter without Android Studio using a terminal and VS Code](/article/flutter-tanpa-android-studio.webp)

This article updates an [older guide by Ihwan on Easyread](https://medium.easyread.co/instalasi-flutter-tanpa-android-studio-2a0876302a68){target="_blank"} (2019, revised 2020) that helped many owners of 120 GB SSD laptops. The idea still holds. Almost every technical detail has changed, and a few of the old commands are harmful if you copy them today.

## What Changed Since the 2020 Guide

The old guide targeted Flutter 1.12, JDK 8, and Android 29. As of October 2026, the latest stable release is Flutter 3.47.1 with Dart 3.13.1, and the official docs ask for Android SDK Platform API 36.

| Component | 2020 guide | 2026 reality |
| :--- | :--- | :--- |
| **Flutter** | 1.12.13 | 3.47.1 (Dart 3.13.1) |
| **JDK** | OpenJDK 8 | JDK 17 or newer |
| **Android platform** | `android-29` | `android-36` |
| **Tools folder** | `C:\Android\tools\bin` | `sdk\cmdline-tools\latest\bin` |
| **SDK variable** | `ANDROID_SDK_ROOT` | `ANDROID_HOME` |
| **`--sdk_root` trick** | Required on every command | Unnecessary with the right folder layout |

Two changes trip people up most. First, the `tools` folder was replaced by `cmdline-tools` long ago, and `sdkmanager` only behaves when it sits inside a subfolder named `latest`. Second, `ANDROID_SDK_ROOT` is deprecated. Use `ANDROID_HOME`, and point it at the SDK folder itself, not its parent.

## What You Need Before You Start

Grab these four downloads. All are free and official.

- **Flutter SDK** from the [manual install page](https://docs.flutter.dev/install/manual).
- **Command-line tools** from the "Command line tools only" section of the [Android Studio download page](https://developer.android.com/studio). At the time of writing, the Windows file is `commandlinetools-win-15859902_latest.zip`.
- **JDK 17 or newer**, for example [Eclipse Temurin](https://adoptium.net/). Pick the `.msi` or `.pkg` installer so `JAVA_HOME` is set for you.
- **VS Code** as your editor.

You also need Git, because Flutter uses it to update itself.

::note
Version numbers here reflect October 2026. Flutter ships a stable release roughly every three months, so check the API level on the [Set up Android development](https://docs.flutter.dev/platform-integration/android/setup) page before copying any command.
::

## Steps to Install Flutter and the Android SDK

The examples use Windows with `C:\Android` as the working folder. On macOS and Linux, swap in a location such as `~/Android`. Avoid paths with spaces like `C:\Program Files`, where Flutter often fails.

::steps
### Get the Folder Layout Right

Extract the Flutter SDK to `C:\Android\flutter`. Then extract the command-line tools. The archive gives you a folder named `cmdline-tools` that directly contains `bin` and `lib`. Move those contents into a `latest` subfolder.

```text
C:\Android
├── flutter
│   └── bin
└── sdk
    └── cmdline-tools
        └── latest
            ├── bin
            └── lib
```

If `bin` sits directly under `cmdline-tools` with no `latest`, `sdkmanager` stops with "Could not determine SDK root". That is the error people used to work around with the `--sdk_root` parameter.

### Set ANDROID_HOME and PATH

Open PowerShell and run these two commands.

```powershell
[Environment]::SetEnvironmentVariable("ANDROID_HOME", "C:\Android\sdk", "User")

$p = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$p;C:\Android\flutter\bin;C:\Android\sdk\cmdline-tools\latest\bin;C:\Android\sdk\platform-tools", "User")
```

On macOS or Linux, add these lines to `~/.zshrc` or `~/.bashrc`.

```bash
export ANDROID_HOME="$HOME/Android/sdk"
export PATH="$PATH:$HOME/Android/flutter/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools"
```

Close the terminal, open a new one, and confirm with `flutter --version` and `java -version`.

### Install the Android SDK Packages

Three packages are enough to build and run an app on a phone.

```bash
sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"
```

Single quotes work too on macOS and Linux. You don't need to install the NDK or CMake by hand. Gradle downloads them when the first build needs them, as long as you have accepted the licenses.

### Accept Licenses and Run Flutter Doctor

```bash
flutter config --android-sdk "C:\Android\sdk"
flutter doctor --android-licenses
flutter doctor
```

Answer `y` to each license. The old complaint about licenses refusing to accept no longer appears as long as you run JDK 17 or newer. `flutter doctor` shows a check mark for "Android toolchain" and a warning for "Android Studio (not installed)". That warning is expected, and you can ignore it.

### Set Up VS Code and Run a Project

Install the **Flutter** extension in VS Code. The Dart extension comes with it. Press `F1`, choose `Flutter: New Project`, then plug in an Android phone with USB debugging turned on. The next section covers the phone setup.

```bash
flutter devices
flutter run
```

Press `F5` in VS Code when you want a debug session with breakpoints and hot reload.
::

::warning
Do not copy `setx path "C:\Android\tools\bin;..."` from the old guide. It overwrites your entire user PATH, so Git, Node, Python, and other tools suddenly vanish from the terminal. The two PowerShell commands above append the new entries and keep what is already there.
::

## Testing Directly on an Android Phone

This guide uses an Android phone as the main test device. There is no emulator to download, and your laptop keeps its RAM. The phone needs a one-time setup through Developer options.

::steps
### Turn On Developer Options

Open **Settings > About phone** and tap **Build number** seven times until you see "You are now a developer". On Xiaomi, Redmi, and POCO phones, tap **MIUI version** or **OS version** instead. Menu names differ slightly by brand, but the entry always lives on the device information page.

### Enable USB Debugging

Go back to Settings, open **Developer options** (usually under **System** or **Additional settings**), and switch on **USB debugging**. Xiaomi users also need **Install via USB**. Without it, `flutter run` stops while installing the app.

### Connect the Phone to Your Laptop

Use a data cable, not a charge-only one. When the phone shows "Allow USB debugging?", tick **Always allow from this computer** and tap **Allow**. On Windows, some brands need the manufacturer's USB driver.

### Confirm Flutter Sees the Phone

```bash
adb devices
flutter devices
```

The phone should appear with the status `device`. A status of `unauthorized` means you haven't approved the prompt on the phone. Then run `flutter run` from the project folder. The first build takes a few minutes while Gradle downloads dependencies.
::

### Cable-Free Debugging over Wi-Fi

Android 11 and newer support wireless debugging. The laptop and phone must be on the same Wi-Fi network. Turn on **Wireless debugging** in Developer options, tap **Pair device with pairing code**, then enter the address and code shown.

```bash
adb pair 192.168.1.10:37123
adb connect 192.168.1.10:41234
```

The ports for `pair` and `connect` are different. Both appear on the phone screen. A cable is still more stable for long work sessions.

::tip
Switch on **Stay awake** in Developer options so the screen stays on while the phone is plugged in. Hot reload feels far better when you don't have to unlock the screen again and again.
::

## An Emulator Without Android Studio, Worth It or Not

You can still create an emulator from the terminal. Think about the original goal first, though: saving storage and RAM. Android system images are large, and the emulator eats the memory you were trying to protect.

On a laptop with 8 GB of RAM, a physical phone is almost always the more comfortable choice. If you still need an emulator, here are the commands.

```bash
sdkmanager "emulator" "system-images;android-36;google_apis;x86_64"
avdmanager create avd -n pixel -k "system-images;android-36;google_apis;x86_64" -d pixel_7
flutter emulators --launch pixel
```

On a Mac with Apple Silicon, replace `x86_64` with `arm64-v8a`.

::tip
No Android phone to test on yet? Run `flutter run -d chrome` or `flutter run -d windows`. You can learn widgets and state management with no emulator at all.
::

## The Trade-Offs You Accept

This setup has a price. You lose three things compared with Android Studio.

- **No graphical SDK manager.** Updating packages means running `sdkmanager --update` yourself, and you have to know the package names.
- **No Android-specific tooling.** Layout Inspector, the native profilers, and the built-in Gradle editor are gone. For a pure Flutter app, Flutter DevTools covers what you need.
- **Native code is harder to edit.** If your project touches a lot of Kotlin or Gradle files, VS Code support feels much thinner.

Beginners learning Flutter rarely notice any of these. Teams that maintain native plugins will.

## Fixing the Most Common Errors

| Error message | Cause | Fix |
| :--- | :--- | :--- |
| `Could not determine SDK root` | `bin` is not inside `cmdline-tools\latest` | Correct the folder layout from the first step |
| `Unable to locate Android SDK` | Flutter doesn't know where the SDK is | Run `flutter config --android-sdk` |
| `UnsupportedClassVersionError` | The JDK is too old, usually JDK 8 | Install JDK 17 or newer, check `JAVA_HOME` |
| `sdkmanager is not recognized` | PATH hasn't been reloaded | Close the terminal and open a new one |
| Phone missing from `flutter devices` | USB debugging is off or the OEM driver is missing | Enable Developer options, install the USB driver |

## Which Setup Should You Choose

::conclusion
Pick the path that matches your machine and your work:

- **Use this setup** if storage is tight, you have 8 GB of RAM or less, and you write pure Flutter apps in VS Code with a physical phone for testing.
- **Add a terminal-made emulator** only when you must test an Android version or screen size you don't own.
- **Install Android Studio** if your work regularly involves Kotlin code, complex Gradle configuration, or native profiling. Time lost to missing tools costs more than a few gigabytes of storage.

Whichever you choose, run `flutter doctor` after every `flutter upgrade`. The API level Flutter asks for rises over time.
::

::faq
::faq-item{question="Can Flutter really run without Android Studio?"}
Yes. Flutter only needs the Android SDK, a JDK, and the Flutter SDK. Android Studio is simply the easiest way to install the Android SDK. The "Android Studio (not installed)" warning in `flutter doctor` does not block builds.
::
::faq-item{question="Which JDK version does Flutter need now?"}
Use JDK 17 or newer. JDK 8 from the old guide can no longer run current versions of Gradle and `sdkmanager`. If you have several JDKs, point Flutter at one with `flutter config --jdk-dir`.
::
::faq-item{question="Do I still need to set ANDROID_SDK_ROOT?"}
No. That variable is deprecated. Set `ANDROID_HOME` to the SDK folder, then run `flutter config --android-sdk` so Flutter remembers the location.
::
::faq-item{question="Can I build a release APK with this setup?"}
Yes. `flutter build apk` and `flutter build appbundle` run entirely from the terminal. App signing is configured through a `key.properties` file and Gradle, with no IDE involved.
::
::faq-item{question="How do I update the Android SDK without the graphical SDK Manager?"}
Run `sdkmanager --update` to update every installed package and `sdkmanager --list_installed` to see what you have. Remove old platform packages with `sdkmanager --uninstall` to keep storage free.
::
