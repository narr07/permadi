**Vue Router** is the official routing library for the Vue.js ecosystem. It maps browser URLs to interface components without triggering a full page reload. This library relies on the HTML5 History API to manage instant client-side page transitions, making it the core foundation of Single Page Application (SPA) architecture.

Modern web applications require interface transitions that feel as fast as desktop software. When users click a navigation menu, the browser does not need to request a new HTML document from the server. The routing system intercepts the URL change, matches it against a list of registered routes, and dynamically swaps the display components on the screen.

For those following a [modern Vue JS tutorial](/blog/modern-vue-js-tutorial), understanding routing mechanics is a mandatory step before building production-scale applications. This article breaks down the basic architecture, fifth-generation feature updates, project installation and configuration steps, and ways to handle reactivity traps that often confuse developers in the field.

## How SPA Navigation and Core Components Work

Traditionally, every link a user clicks triggers a full network request to the server. SPA architecture breaks this slow cycle by moving the URL matching logic directly to the client browser.

![Workflow diagram comparing client-side browser routing and traditional server page reloads](/article/tech-vue-router-guide-ilustrasi.webp)

This system works using three primary instruments from the `vue-router` package:

1. **`createRouter()` and `createWebHistory()`**: Initialization functions that assemble the router instance and enable HTML5-based history tracking (`pushState`, `replaceState`, and the `popstate` event).
2. **`<RouterView>`**: A container component (dynamic slot) placed in the main template. Page components matching the active URL path will render exactly where this element is positioned.
3. **`<RouterLink>`**: A declarative component replacing the standard HTML `<a>` tag. This element prevents the browser's default page reload while automatically managing active CSS classes.

When choosing a routing history mode, you need to weigh the characteristics of HTML5 mode against Hash mode based on the server environment where the application will run:

| Feature & Characteristic | `createWebHistory()` (HTML5 Mode) | `createWebHashHistory()` (Hash Mode) |
| :--- | :--- | :--- |
| **URL Format** | Clean and standard (`permadi.dev/article`) | Uses a hash symbol (`permadi.dev/#/article`) |
| **Core Mechanism** | Relies on the HTML5 History API (`pushState`) | Monitors character changes after the `#` symbol |
| **Server Configuration** | Requires setting a fallback rewrite to `index.html` | No special server configuration needed |
| **SEO Compatibility** | Highly search engine and web analytics friendly | Suboptimal for search engine indexing |
| **Ideal Scenario** | Production web applications, public portals, PWAs | Local hybrid applications (Cordova/Electron) or limited static hosting |

## What Is New in Vue Router 5?

In 2026, core maintainer Eduardo San Martin Morote (`@posva`) released **Vue Router 5**. This major update answers a long-standing dilemma among Vue developers: writing route lists manually in an array, or switching to folder structure-based routing like when [learning Nuxt JS](/blog/introduction-to-nuxt-js-vue-framework-ssr-ssg).

This fifth version release integrates `unplugin-vue-router` capabilities directly into the core package through the `vue-router/vite` or `vue-router/unplugin` subpaths. Pure SPA developers can now use file-based routing complete with typed routes and strictly verified TypeScript parameters without installing additional third-party dependencies.

The good news is that Vue Router 5 is designed to be backward compatible without breaking legacy code for version 4 users. If your project still uses traditional static route array configurations, the entire codebase continues to run smoothly without needing a rewrite.

Aside from unifying file-based routing, version 5 brings two major technical leaps:

* **Experimental Data Loaders (`vue-router/experimental`)**: This feature binds data fetching directly to the routing cycle before the component finishes rendering. This approach separates asynchronous data loading logic from UI components, aligning with modern loader patterns seen in TanStack Router or Remix.
* **Native View Transitions API Integration**: You can now tie the browser's native `document.startViewTransition()` function into navigation guards (`beforeEach` and `afterEach`). This feature produces smooth morphing animations between pages without burdening the application bundle with external animation libraries.

## How to Install and Configure Vue Router

The **Vue Router** installation process for a Vite-based Vue 3 project runs directly through the package management terminal. Follow these structured steps to set up a production-ready routing architecture.

::steps
### Package Installation via Terminal
Run the installation command in your project root directory to download the latest version:

```bash
npm install vue-router@5
## Or if you use pnpm:
pnpm add vue-router@5
```

### Create the Router Configuration File
Create a new directory and file at `src/router/index.ts`. In this file, you define the URL path map, lazy loading, scroll position settings, and a 404 catch-all page.

```typescript
import { createRouter, createWebHistory } from 'vue-router'
import HomeView from '../views/HomeView.vue'

export const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/',
      name: 'home',
      component: HomeView
    },
    {
      path: '/about',
      name: 'about',
      // Lazy loading via Dynamic Import to keep the initial bundle size light
      component: () => import('../views/AboutView.vue')
    },
    {
      path: '/user/:id',
      name: 'user-detail',
      component: () => import('../views/UserDetailView.vue')
    },
    // Catch-all route to handle 404 Not Found pages
    {
      path: '/:pathMatch(.*)*',
      name: 'not-found',
      component: () => import('../views/NotFoundView.vue')
    }
  ],
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) {
      return savedPosition
    }
    return { top: 0 }
  }
})
```

### Register the Router Instance to the Main Application
Open the `src/main.ts` file and attach the router instance to the Vue application before calling the `.mount()` method.

```typescript
import { createApp } from 'vue'
import App from './App.vue'
import { router } from './router'

const app = createApp(App)

app.use(router)
app.mount('#app')
```

### Add Navigation Components to the Main Template
Open `src/App.vue` and place `<RouterLink>` as the navigation menu and `<RouterView>` as the page rendering canvas.

```vue
<template>
  <header>
    <nav>
      <RouterLink to="/">Home</RouterLink>
      <RouterLink :to="{ name: 'about' }">About Us</RouterLink>
    </nav>
  </header>

  <main>
    <RouterView />
  </main>
</template>
```
::

Pay attention to the `scrollBehavior` property in the configuration above. Michael Thiessen, in his book *Nuxt Tips Collection*, notes that SPA applications natively retain the screen scroll position when users change pages. Returning the `{ top: 0 }` object ensures the screen automatically scrolls back to the very top like a traditional website, while the `savedPosition` condition keeps the scroll position accurate when users press the browser's Back button.

The same applies to the catch-all `/:pathMatch(.*)*` route at the bottom. Nail Titah, in *The SEO Guide*, emphasizes the importance of handling broken links by providing a dedicated 404 page. Letting visitors see a blank white screen due to an unregistered route ruins the user experience and increases the bounce rate.

## Navigation Patterns: Interactive Buttons and Route Redirection

In real-world interface development, navigation does not always take the form of plain text links. Designers often create call-to-action buttons or require automatic redirection after a user completes a task.

### Handling Button Navigation

Many beginner developers make accessibility mistakes when designing navigation buttons in Vue Router. They wrap a `<button>` element inside `<RouterLink>`, or attach a `@click="router.push('/destination')"` event to a `<div>` or an `<a>` tag without an `href` attribute. These practices break keyboard navigation, confuse screen readers, and disable right-click or middle-click features for opening new tabs.

There are two clean ways to handle button navigation based on the context of use:

**1. Accessible Declarative Approach (`custom` Slot)**
If the button purely functions to move the user to another page, use the `custom` property along with `v-slot` on `<RouterLink>`.

```vue
<template>
  <RouterLink to="/payment" custom v-slot="{ navigate, isActive }">
    <button
      type="button"
      :class="['btn-primary', { 'btn-active': isActive }]"
      @click="navigate"
    >
      Proceed to Payment
    </button>
  </RouterLink>
</template>
```

**2. Programmatic Navigation Approach (Imperative)**
If the page transition should only happen after an asynchronous process finishes (like form validation or saving data to an API), use the `useRouter()` composable. This concept is similar to the `navigateTo` helper function explained by Michael Thiessen in *Nuxt Tips Collection* for handling route changes within script code.

```vue
<script setup lang="ts">
import { useRouter } from 'vue-router'

const router = useRouter()

const saveForm = async () => {
  const success = await sendDataToServer()

  if (success) {
    // Move to a named route carrying an ID parameter
    router.push({ name: 'user-detail', params: { id: '402' } })
  }
}
</script>

<template>
  <button type="button" @click="saveForm">
    Save & Continue
  </button>
</template>
```

### Setting Up Route Redirection (Redirect vs Alias)

Changing old URL structures to new paths requires proper redirect configurations in Vue Router. You can define these redirects directly in the route table using static strings, named route objects, or dynamic functions that retain query parameters.

```typescript
const routes = [
  // Simple static redirect
  {
    path: '/old-profile',
    redirect: '/account/profile'
  },
  // Dynamic redirect retaining search queries (?q=...)
  {
    path: '/search-product',
    redirect: to => {
      return { path: '/catalog', query: to.query }
    }
  }
]
```

Beyond the route configuration level, redirects are often placed inside Navigation Guards (`beforeEach`) to secure member-only pages or admin panels:

```typescript
router.beforeEach((to, from) => {
  const isLoggedIn = checkUserToken()

  if (to.meta.requiresAuth && !isLoggedIn) {
    // Redirect to the login page and save the original destination URL in the query
    return {
      name: 'login',
      query: { redirect: to.fullPath }
    }
  }
})
```

::note
**Understand the Difference Between Redirect and Alias:** As explained by Michael Thiessen in *Nuxt Tips Collection*, `redirect` changes the URL in the browser address bar to the new destination URL. Conversely, if you want several different URLs to render the exact same page component without changing the URL text in the user's browser, use the `alias: '/alternative-path'` property.
::

## Common Vue Router Pitfalls and How to Avoid Them

Even though the Vue Router API looks straightforward, there are three technical traps that often trigger hidden bugs in production applications, especially when dealing with Vue 3's reactivity system and server configurations.

### 1. Losing Reactivity When Destructuring `useRoute()`

The most common mistake seen during code reviews is destructuring the `useRoute()` object directly at the top level of `<script setup>`.

```typescript
// WRONG: The userId value will not update when the URL changes from /user/1 to /user/2
const { params } = useRoute()
const userId = params.id
```

The object returned by `useRoute()` is a reactive proxy. Direct destructuring breaks its reactivity bindings. When a user moves from `/user/1` to `/user/2`, Vue reuses the same component instance for performance efficiency, leaving the `userId` value frozen at `1`.

To resolve this, wrap route property access inside `computed()` or use the `@vueuse/router` library (`useRouteParams`):

```typescript
import { computed } from 'vue'
import { useRoute, useRouter } from 'vue-router'

const route = useRoute()
// RIGHT: Reactivity is fully maintained
const userId = computed(() => route.params.id)

// Alternative using currentRoute which is a shallowRef
const router = useRouter()
const activePath = computed(() => router.currentRoute.value.path)
```

In the book *Vue Tips Collection*, Michael Thiessen also highlights that `useRouter().currentRoute` is actually a `shallowRef`. Understanding this shallow reference nature is essential when building large-scale applications or working in Server-Side Rendering (SSR) environments to avoid hydration mismatch issues and state leaks across client requests.

### 2. Server 404 Errors Upon Refresh in History Mode

When an application is compiled for a production build using `createWebHistory()`, navigating from the homepage to `/about` runs normally because JavaScript handles it in the browser. However, once a user presses the Refresh button (F5) while on the `/about` URL, the browser requests the physical `/about` file directly from the web server.

Because SPA applications only have one main physical file, `index.html`, servers like Nginx or Apache will respond with a `404 Not Found` error message.

::warning
**Mandatory Server Fallback Configuration:** When deploying SPA applications to hosting services or a VPS, ensure you add a fallback rewrite rule so all URL requests not pointing to static files are redirected back to `index.html`. If you deploy applications to modern infrastructure as discussed in the [Cloudflare Workers edge architecture guide](/blog/cloudflare-workers-edge-architecture), enable the Single-Page Application (SPA) fallback option in its static asset configuration.
::

### 3. Ignoring Bundle Splitting (Lazy Loading)

Statically importing all page components at the top of the `router/index.ts` file forces Vite to bundle all pages into one massive JavaScript file. As a result, the application's initial load time slows down, lowering your web performance scores.

Always use the dynamic import syntax `component: () => import('../views/PageName.vue')` for every secondary route. Vite automatically splits each page into separate file chunks that download only when a user visits that route. This practice effectively preserves initial load metrics, aligning with the [Core Web Vitals optimization guide](/blog/core-web-vitals-optimization-guide) to ensure interfaces remain responsive.

::faq
  :::faq-item
  ---
  question: When should I use router.push() instead of router.replace()?
  ---
  Use `router.push()` for normal navigation because this method adds a new entry to the browser's history stack, allowing users to press the Back button to return. Use `router.replace()` when you want to overwrite the current history entry without adding a new record, such as after a user successfully logs in or during an authorization page redirect so users do not return to the login form page when pressing the back button.
  :::

  :::faq-item
  ---
  question: What is the main difference between createWebHistory() and createWebHashHistory()?
  ---
  `createWebHistory()` leverages the HTML5 History API to produce clean standard URLs (like `domain.com/product`), but it requires an `index.html` fallback setting on the server side. Conversely, `createWebHashHistory()` inserts a hash symbol into the URL (`domain.com/#/product`) which functions instantly on any static server without extra configuration, but is less optimal for link aesthetics and SEO indexing.
  :::

  :::faq-item
  ---
  question: Will Vue Router 4 code break if upgraded to Vue Router 5?
  ---
  No. Vue Router 5 is designed to be backward compatible for users with array-based route configurations from version 4. The main updates in version 5 include merging file-based routing features (`unplugin-vue-router`) directly into the core package, strictly typed parameter verification, and the addition of experimental Data Loaders features.
  :::

  :::faq-item
  ---
  question: How do I secure admin pages in a Vue SPA application?
  ---
  Add the `meta: { requiresAuth: true }` property to the admin page route object, then attach a Global Navigation Guard using `router.beforeEach()`. Inside that function, check the user's authentication status and return the destination route object for the login page if the user does not have access yet.
  :::

::conclusion
Mastering **Vue Router** is not just about memorizing how to switch views from one component to another; it involves designing an accessible, fast, and robust navigation architecture in a production environment. The arrival of **Vue Router 5** gives you full flexibility to choose between explicit classic array route configurations or modern file-based routing with strict TypeScript data type support.

As a practical next step, audit the routing code in your current Vue project:
1. Ensure all routes besides the main homepage use lazy loading (`() => import(...)`) to cut down initial download loads.
2. Replace all `<button>` or `<div>` elements using `@click="router.push"` for pure navigation links with `<RouterLink>` components to maintain accessibility.
3. Add a catch-all route `/:pathMatch(.*)*` along with a `scrollBehavior` configuration to maintain smooth user navigation in all conditions.
