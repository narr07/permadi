Mempelajari **tutorial Vue.js** modern berarti memahami cara kerja antarmuka deklaratif berbasis **Composition API**, sistem reaktivitas otomatis, serta arsitektur Single File Component (`.vue`). Dibuat oleh Evan You, *framework* JavaScript progresif ini memudahkan kita membangun antarmuka interaktif, mulai dari komponen kecil yang terisolasi hingga aplikasi *single-page* skala besar dengan kurva belajar yang ramah dan performa tinggi.

Banyak programmer pemula terjebak mempelajari materi lawas yang masih memakai Options API, Vue CLI, atau Vuex. Padahal, standar industri saat ini sudah bergeser penuh ke ekosistem Vue 3.5+ yang mengandalkan Vite sebagai *build tool* dan Pinia untuk mengelola *state*. Panduan ini membedah fondasi Vue langsung dari praktik terbaik terkini agar kode Anda bersih, mudah diuji, dan siap masuk ke lingkungan produksi.

## Mengapa Belajar Vue.js di Ekosistem Frontend Saat Ini?

Vue dirancang sebagai *incrementally adoptable framework*. Anda bisa menyisipkannya ke satu halaman HTML sederhana untuk menggantikan manipulasi DOM manual, atau menjadikannya fondasi aplikasi web berskala *enterprise*. Kemampuan adaptasi ini menempatkan Vue di jajaran tiga besar *framework* frontend global bersama React dan Angular, dengan komunitas aktif yang tersebar luas di Indonesia maupun mancanegara.

Dario Benevento dalam buku *Frontend Development (UIUX & Psychology)* menjelaskan bahwa Vue bertumpu pada dua pilar utama: *declarative templates* dan *component composition*. Pendekatan deklaratif membebaskan developer dari kerepotan memilih elemen secara imperatif memakai `document.querySelector`. Anda cukup mendefinisikan *state* aplikasi, lalu Vue secara otomatis memperbarui tampilan DOM setiap kali *state* tersebut berubah.

Lompatan performa pada rilis **Vue 3.5 (Tengen Toppa Gurren Lagann)** semakin mengukuhkan posisinya. Perombakan sistem reaktivitas internal menggunakan struktur *doubly-linked list* berhasil memangkas konsumsi memori hingga 56% dan mempercepat operasi *array* reaktif hingga 10 kali lipat tanpa merusak kompatibilitas API yang sudah ada. Tim inti Vue juga tengah mematangkan **Vapor Mode** menuju rilis Vue 3.6, sebuah strategi kompilasi opsional tanpa Virtual DOM (*opt-in* melalui `<script setup vapor>`) yang menerjemahkan komponen langsung menjadi instruksi DOM murni untuk halaman berbeban tinggi.

Bagi Anda yang baru meniti jalur karier sebagai [web developer modern](/id/blog/panduan-apa-itu-web-developer), menguasai Vue memberikan pijakan kokoh sebelum melangkah ke kerangka kerja *full-stack* seperti [Nuxt.js untuk kebutuhan SSR dan SSG](/id/blog/mengenal-nuxt-js-framework-vue-ssr-ssg).

## Paradigma Inti: Single File Component dan Composition API

Sebelum menulis baris kode pertama, Anda wajib memahami wadah kerja utama di Vue yang bernama **Single File Component (SFC)**. Satu file berekstensi `.vue` merangkum tiga lapisan antarmuka sekaligus dalam satu modul yang rapi:

![Diagram visual struktur tiga lapisan komponen web dengan aliran data terhubung](/article/tech-vue-js-tutorial-ilustrasi.webp)

1. **`<template>`**: Berisi struktur markah HTML deklaratif tempat data dirender.
2. **`<script setup>`**: Tempat menulis logika JavaScript atau TypeScript, mendefinisikan *state* reaktif, dan mengatur siklus hidup komponen.
3. **`<style scoped>`**: Berisi aturan CSS yang diisolasi khusus untuk komponen tersebut agar tidak merusak gaya visual komponen lain.

Sejak kehadiran Vue 3, komunitas resmi menetapkan **Composition API** (khususnya dengan atribut `<script setup>`) sebagai standar utama, menggantikan Options API dari era Vue 2.

| Aspek Perbandingan | Composition API (`<script setup>`) | Options API (Standar Lama Vue 2) |
| :--- | :--- | :--- |
| **Organisasi Kode** | Dikelompokkan berdasarkan fitur atau fungsi logika | Terpecah ke dalam blok `data`, `methods`, `computed` |
| **Ketergantungan Konteks** | Bebas konteks (*context-free*), tidak memakai `this` | Sangat bergantung pada konteks *runtime* `this` |
| **Pemakaian Ulang Logika** | Mudah diekstrak menjadi fungsi *Composable* | Memakai *Mixins* yang rawan bentrok penamaan |
| **Dukungan TypeScript** | Inferensi tipe data alami dan akurat tanpa friksi | Membutuhkan pembungkus tipe tambahan yang rumit |
| **Ukuran Bundle Produksi** | Ramah *tree-shaking* dan minifikasi kode | Properti objek opsi sulit dikompresi oleh *bundler* |

Michael Thiessen dalam buku *Vue Tips Collection (Second Edition)* menyoroti alasan utama mengapa Composition API begitu revolusioner: sifatnya yang **bebas konteks (*context-free*)**. Pada Options API, developer sering menempelkan properti global ke konteks komponen sehingga logika terikat erat pada objek `this` dan sulit dipisahkan ke file eksternal. Tanpa ikatan `this`, setiap fungsi reaktif di Composition API bekerja selayaknya fungsi JavaScript biasa yang mudah dipindahkan, diuji secara terpisah (*unit test*), bahkan dijalankan secara *inline* di dalam satu komponen.

## Tutorial Vue.js: Langkah Praktis Membangun Komponen Pertama

Kita akan langsung membuat proyek baru dan merakit komponen interaktif pertama menggunakan perkakas standar modern.

::steps
### Inisialisasi Proyek dengan Vite

Vue CLI sudah resmi berstatus *maintenance mode*. Sekarang kita menggunakan `create-vue`, perkakas resmi berbasis **Vite** yang menyalakan server pengembangan berbasis ES modules secara instan. Buka terminal Anda dan jalankan perintah berikut:

```bash
npm create vue@latest
```

Terminal akan menampilkan beberapa pertanyaan konfigurasi. Untuk tahap belajar dasar, beri nama proyek Anda, pilih **Yes** pada opsi TypeScript (opsional, tetapi sangat disarankan), Pinia, dan Vue Router sesuai kebutuhan, lalu lanjutkan instalasi paket:

```bash
cd nama-proyek-anda
npm install
npm run dev
```

### Memahami Reaktivitas Dasar (`ref` dan `computed`)

Buka proyek di editor kode Anda, lalu perhatikan bagaimana Vue mengelola perubahan data. Kita menggunakan fungsi `ref()` untuk membungkus nilai primitif maupun objek agar bersifat reaktif, serta `computed()` untuk menghasilkan nilai turunan yang dihitung ulang secara otomatis saat sumber datanya berubah.

Buat atau ubah file `src/components/UserProfileCard.vue` dengan kode berikut:

```vue
<template>
  <section class="profile-card">
    <h2>Halo, {{ formattedHandle }}</h2>
    <p>Status Akun: <strong>{{ statusLabel }}</strong></p>

    <div class="form-group">
      <label for="username-input">Ubah Username:</label>
      <input
        id="username-input"
        v-model.trim="username"
        type="text"
        placeholder="Ketik username..."
      />
    </div>

    <button type="button" @click="toggleStatus">
      Ubah Status Online
    </button>
  </section>
</template>

<script setup lang="ts">
import { ref, computed } from 'vue'

// 1. State reaktif menggunakan ref
const username = ref('dinarpermadi')
const isOnline = ref(true)

// 2. Computed property: otomatis diperbarui saat username atau isOnline berubah
const formattedHandle = computed(() => `@${username.value.toLowerCase()}`)
const statusLabel = computed(() => (isOnline.value ? 'Aktif' : 'Offline'))

// 3. Fungsi mutasi state biasa
function toggleStatus() {
  isOnline.value = !isOnline.value
}
</script>

<style scoped>
.profile-card {
  padding: 1.5rem;
  border: 1px solid #cbd5e1;
  border-radius: 0.5rem;
  max-width: 400px;
}
.form-group {
  margin: 1rem 0;
  display: flex;
  flex-direction: column;
  gap: 0.5rem;
}
</style>
```

Perhatikan direktif `v-model.trim="username"` pada elemen `<input>`. Direktif ini menciptakan *two-way data binding* (ikatan data dua arah) sekaligus memangkas spasi kosong di awal dan akhir teks secara otomatis. Saat pengguna mengetik, variabel `username` langsung diperbarui, dan `formattedHandle` ikut berubah seketika.

### Komunikasi Antar-Komponen dengan Props dan Emits

Aplikasi nyata tersusun dari banyak komponen yang saling bertukar data. Komponen induk (*parent*) mengirim data ke komponen anak (*child*) melalui **Props**, sedangkan komponen anak mengirim sinyal peristiwa kembali ke induk melalui **Emits**.

Sejak Vue 3.5, fitur **Reactive Props Destructure** telah stabil sepenuhnya. Anda bisa langsung melakukan *destructuring* pada `defineProps` dan memberikan nilai bawaan (*default value*) menggunakan sintaks JavaScript murni tanpa kehilangan sifat reaktifnya:

```vue
<script setup lang="ts">
// Destrukturisasi props secara reaktif (Stabil di Vue 3.5+)
const { title = 'Judul Standar', initialCount = 0 } = defineProps<{
  title?: string
  initialCount?: number
}>()

// Mendefinisikan event yang bisa dikirim ke komponen induk
const emit = defineEmits<{
  updateCount: [newValue: number]
}>()

function notifyParent() {
  emit('updateCount', initialCount + 1)
}
</script>

<template>
  <div class="counter-box">
    <h3>{{ title }}</h3>
    <p>Nilai awal dari induk: {{ initialCount }}</p>
    <button type="button" @click="notifyParent">Tambah & Lapor ke Induk</button>
  </div>
</template>
```

### Mengekstrak Logika Menjadi Composable

Ketika satu logika reaktif mulai dibutuhkan oleh beberapa komponen berbeda, jangan menyalin ulang kodenya. Ekstrak logika tersebut ke dalam folder `src/composables/`.

```ts
// src/composables/useCounter.ts
import { ref, computed } from 'vue'

export function useCounter(initialValue = 0) {
  const count = ref(initialValue)
  const doubleCount = computed(() => count.value * 2)

  function increment() {
    count.value++
  }

  function decrement() {
    count.value--
  }

  return {
    count,
    doubleCount,
    increment,
    decrement
  }
}
```

Kini, komponen mana pun cukup memanggil `const { count, increment } = useCounter(10)` di dalam `<script setup>` untuk mendapatkan fungsi penghitung yang utuh dan terisolasi.
::

## Arsitektur Kode Bersih: Memisahkan `composables` dan `utils`

Salah satu tanda kematangan seorang *frontend engineer* terletak pada kemampuannya menjaga batas arsitektur folder. Saat proyek membesar, banyak developer pemula mencampuradukkan fungsi pembantu biasa dengan fungsi reaktif Vue di dalam satu folder yang sama.

Michael Thiessen dalam buku *Nuxt Tips Collection* menekankan pentingnya memisahkan disiplin antara folder **`utils`** dan **`composables`**:

* **Folder `utils/` (Fungsi Murni)**: Hanya boleh berisi fungsi algoritmik murni (*pure functions*) yang bersifat deterministik, tanpa *state* reaktif maupun siklus hidup komponen. Contohnya adalah pemformat mata uang Rupiah, kalkulator tanggal, atau validator alamat surel. Jika diberi input yang sama, fungsi ini selalu mengembalikan output yang sama tanpa efek samping.
* **Folder `composables/` (Logika Stateful)**: Berisi fungsi yang memanfaatkan API reaktivitas Vue (`ref`, `computed`, `watch`) atau *lifecycle hooks* (`onMounted`, `onUnmounted`). Namanya wajib diawali dengan kata kerja `use`, seperti `useCounter`, `useFetchUser`, atau `useDarkMode`.

::tip
Jika sebuah fungsi tidak mengimpor apa pun dari paket `'vue'`, hampir dapat dipastikan fungsi tersebut adalah *utility* murni dan harus diletakkan di dalam folder `utils/`, bukan `composables/`.
::

## Integrasi Backend: Mengapa Duet Vue.js dan Laravel Begitu Populer?

Banyak developer backend yang mencari **tutorial Vue.js Laravel** karena kedua teknologi ini memiliki sejarah kemitraan yang sangat erat di industri pengembangan web. Laravel menyertakan dukungan kelas satu untuk Vue sejak lama, tetapi cara mengintegrasikannya kini jauh lebih ringkas dibandingkan beberapa tahun silam.

Dulu, developer harus membangun dua repositori terpisah: Laravel sebagai REST API dengan autentikasi token JWT yang rumit, dan Vue sebagai SPA terpisah yang memanggil endpoint melalui Axios. Pendekatan tersebut sering kali terlalu berat untuk tim skala kecil hingga menengah.

Di ekosistem Laravel 11+ saat ini, pola standar yang mendominasi adalah perpaduan **Laravel + Inertia.js + Vue 3**. Inertia bertindak sebagai jembatan penghubung yang memungkinkan kita membangun aplikasi *monolith* modern berwajah SPA:

1. **Tanpa API Terpisah**: Anda tetap menulis *routing* dan *controller* standar di Laravel.
2. **Pengiriman Data Langsung**: Alih-alih mengembalikan tampilan Blade tradisional, *controller* Laravel merender komponen Vue secara langsung dan menyuntikkan data sebagai properti.
3. **Antarmuka Reaktif Penuh**: Data dari controller diterima sebagai `props` di dalam file komponen `.vue`. Halaman berpindah secara instan di sisi klien tanpa muat ulang penuh (*full page reload*) dan tanpa kerepotan mengelola token API terpisah.

Jika Anda bekerja di ekosistem JavaScript murni tanpa PHP, peran serupa ditangani dengan sangat rapi oleh Nuxt bersama komponen siap pakai dari [Nuxt UI untuk membangun antarmuka modern](/id/blog/nuxt-ui-panduan-desain-modern).

## 5 Kesalahan Umum Pemula di Vue 3 dan Cara Menghindarinya

Memahami sintaks dasar hanyalah separuh perjalanan. Separuh lainnya adalah mengenali jebakan reaktivitas yang sering membuat aplikasi gagal memperbarui tampilan atau mengalami kebocoran memori (*memory leak*).

### 1. Lupa Menulis `.value` di Dalam Blok Script

Di dalam `<template>`, Vue membuka bungkus nilai reaktif secara otomatis (*auto-unwrapping*) sehingga Anda cukup menulis `{{ count }}`. Namun, di dalam blok `<script setup>`, variabel `ref` adalah sebuah objek pembungkus. Menulis `count++` secara langsung tidak akan berjalan; Anda wajib mengaksesnya lewat properti `count.value++`.

### 2. Memutus Reaktivitas `reactive()` Saat Destructuring

Berbeda dengan `defineProps` di Vue 3.5+ yang sudah dikompilasi khusus, melakukan *destructuring* langsung pada objek `reactive()` biasa akan memutus koneksi proksi reaktifnya:

```ts
import { reactive, toRefs } from 'vue'

const user = reactive({ name: 'Andi', age: 20 })

// SALAH: variabel name dan age kehilangan sifat reaktif
const { name, age } = user

// BENAR: gunakan helper toRefs agar tetap reaktif
const { name: reactiveName, age: reactiveAge } = toRefs(user)
```

Karena jebakan inilah komunitas modern menyarankan pemakaian `ref()` sebagai standar utama untuk semua tipe data.

### 3. Mengabaikan Pembersihan Watcher dan Event Listener

Ketika Anda memasang *interval timer*, langganan WebSocket, atau *event listener* DOM manual di dalam pengamat (`watch`) maupun `onMounted`, pastikan efek samping tersebut dibersihkan saat pengamat diperbarui atau komponen dihancurkan. Di Vue 3.5+, manfaatkan fungsi bawaan `onWatcherCleanup()` atau siklus `onUnmounted`:

```ts
import { ref, watch, onWatcherCleanup } from 'vue'

const searchQuery = ref('')

watch(searchQuery, (newQuery) => {
  const controller = new AbortController()
  fetch(`/api/search?q=${newQuery}`, { signal: controller.signal })

  // Batalkan request sebelumnya jika pengguna mengetik lagi sebelum selesai
  onWatcherCleanup(() => {
    controller.abort()
  })
})
```

### 4. Mengakses Elemen DOM dengan `document.querySelector`

Jangan mengambil elemen HTML menggunakan selektor DOM manual di dalam komponen Vue. Gunakan fitur `useTemplateRef()` yang diperkenalkan secara stabil di Vue 3.5 untuk mengikat referensi elemen secara aman dan terisolasi:

```vue
<script setup lang="ts">
import { useTemplateRef, onMounted } from 'vue'

const inputElement = useTemplateRef<HTMLInputElement>('search-input')

onMounted(() => {
  inputElement.value?.focus()
})
</script>

<template>
  <input ref="search-input" type="text" />
</template>
```

### 5. Memaksa Render Ulang dengan `$forceUpdate`

Saat tampilan DOM tidak berubah sesuai harapan, pemula kerap tergoda memanggil `$forceUpdate()`. Michael Thiessen dalam *Vue Tips Collection (Second Edition)* mengingatkan bahwa pemaksaan render hampir selalu menandakan adanya kesalahan pada mutasi data reaktif Anda.

::warning
Jika Anda benar-benar perlu mengatur ulang (*reset*) siklus hidup komponen pihak ketiga dari nol, jangan gunakan `$forceUpdate`. Gunakan **Key-Changing Technique**: berikan atribut `:key="uniqueKey"` pada komponen tersebut, lalu ubah nilai variabel `uniqueKey`. Vue akan menghancurkan instans lama secara bersih dan memasang (*mount*) instans baru dari awal.
::

  :::faq-item
  ---
  question: Apakah pemula harus belajar Options API dulu atau langsung Composition API?
  ---
  Langsung pelajari **Composition API** dengan sintaks `<script setup>`. Seluruh pustaka ekosistem modern dan dokumentasi resmi terbaru berpusat pada Composition API. Anda cukup mengenali konsep Options API secara sekilas hanya untuk keperluan membaca atau memelihara kode warisan (*legacy code*).
  :::

  :::faq-item
  ---
  question: Kapan sebaiknya menggunakan ref() dibandingkan reactive()?
  ---
  Gunakan `ref()` sebagai pilihan utama (*default*) di segala situasi, baik untuk menyimpan nilai primitif (string, angka, boolean) maupun struktur data kompleks seperti objek dan *array*. Penulisan `.value` yang konsisten pada `ref()` menjaga kejelasan kode dan memudahkan proses *refactoring* maupun *destructuring*.
  :::

  :::faq-item
  ---
  question: Bagaimana cara paling efisien menghubungkan Vue 3 dengan Laravel?
  ---
  Gunakan paket starter resmi Laravel Breeze dengan opsi **Vue dan Inertia.js**. Arsitektur ini mengizinkan Anda membangun antarmuka Single Page Application menggunakan komponen `.vue` sambil tetap memanfaatkan sistem *routing* dan *controller* bawaan Laravel tanpa perlu menyiapkan endpoint REST API terpisah.
  :::

  :::faq-item
  ---
  question: Apakah Vue.js masih relevan dibandingkan React dan Next.js?
  ---
  Sangat relevan. Vue menawarkan kurva belajar yang ramah, kompilasi super cepat berkat Vite, serta sistem reaktivitas yang tidak memicu *re-render* seluruh sub-pohon komponen sehingga Anda tidak perlu direpotkan oleh optimasi manual seperti `useMemo` atau `useCallback`. Untuk kebutuhan SSR kelas produksi, Vue juga didukung penuh oleh ekosistem Nuxt.
  :::

1. **Bangun Proyek Kecil**: Inisialisasi proyek Vue 3 memakai Vite, lalu buat aplikasi pencatat tugas (*to-do list*) yang menerapkan `ref`, `computed`, serta komunikasi komponen lewat *props* dan *emits*.

3. **Pelajari Perkakas Ekosistem**: Setelah nyaman dengan komponen dasar, pelajari **Pinia** untuk manajemen *state* terpusat, **Vue Router** untuk navigasi halaman, lalu jajaki kerangka kerja Nuxt untuk kebutuhan aplikasi skala produksi.
