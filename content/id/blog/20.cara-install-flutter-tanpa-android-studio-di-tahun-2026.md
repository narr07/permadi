Anda bisa menerapkan **cara install Flutter tanpa Android Studio di tahun 2026** hanya dengan tiga komponen inti: **Flutter SDK**, **Java Development Kit (JDK 17 atau 21)**, dan **Android SDK Command-line Tools**. Seluruh kode ditulis melalui editor ringan seperti Visual Studio Code (VS Code) sehingga konsumsi RAM dan ruang penyimpanan komputer tetap hemat.

Metode berbasis *Command-line Tools* murni hanya membutuhkan ruang sekitar 1,5 hingga 3 GB tergantung versi platform yang Anda pasang. Bandingkan dengan instalasi penuh Android Studio beserta *bundle* bawaannya yang menyedot 5 hingga 10 GB ruang penyimpanan dan memakan 2 sampai 4 GB RAM saat diam (*idle*).

Tulisan ini memperbarui [panduan lama karya Ihwan di Easyread](https://medium.easyread.co/instalasi-flutter-tanpa-android-studio-2a0876302a68){target="_blank"} yang dulu menolong banyak pemilik laptop berkapasitas SSD terbatas. Gagasan utamanya masih relevan, tetapi hampir semua detail teknisnya telah berubah. Menyalin mentah-mentah perintah dari panduan lawas justru akan merusak konfigurasi sistem Anda hari ini.

## Apa yang Berubah Sejak Panduan Versi Lama

Panduan tahun 2020 ditulis untuk era Flutter 1.x, JDK 8, dan Android API 29. Saat ini, Google Play Console mewajibkan target API minimum di rentang Android 14 (API 34) hingga Android 15 dan 16 (API 35/36), sementara ekosistem Gradle modern menuntut versi Java yang jauh lebih baru.

| Komponen | Panduan Lama (2020) | Standar Baru (2026) |
| :--- | :--- | :--- |
| **Versi Java (JDK)** | OpenJDK 8 | OpenJDK 17 atau 21 LTS |
| **Platform Android** | `android-29` | `android-35` atau `android-36` |
| **Struktur Folder Tools** | `C:\Android\tools\bin` | `sdk\cmdline-tools\latest\bin` |
| **Variabel Lingkungan** | `ANDROID_SDK_ROOT` | `ANDROID_HOME` |
| **Parameter `--sdk_root`** | Wajib di setiap perintah | Tidak perlu jika struktur folder tepat |
| **Konsumsi RAM Editor** | Android Studio (2–4 GB) | VS Code / Cursor (300–600 MB) |
| **Ruang Penyimpanan** | Bundle penuh (5–10 GB) | CLI murni (1,5–3 GB) |

Ada tiga perubahan arsitektur yang paling sering menjebak pengembang saat melakukan instalasi mandiri:

1. **Kewajiban JDK 17 atau 21 LTS:** Android Gradle Plugin (AGP) versi 8.x ke atas menolak berjalan di atas JDK 8 atau JDK 11. Di sisi lain, memakai JDK non-LTS yang terlalu baru (seperti JDK 23) kerap memicu masalah kompatibilitas pada skrip Gradle.
2. **Struktur Subfolder `latest`:** Direktori `tools` sudah lama dihapus. Perkakas `sdkmanager` kini wajib diletakkan di dalam struktur bertingkat `<ANDROID_HOME>/cmdline-tools/latest/bin/`. Tanpa folder `latest`, terminal akan terus menolak perintah Anda.
3. **Depresiasi `ANDROID_SDK_ROOT`:** Google secara resmi memensiunkan variabel `ANDROID_SDK_ROOT` dan menetapkan `ANDROID_HOME` sebagai penunjuk tunggal direktori SDK Android.

Pendekatan berbasis terminal ini bukan sekadar akal-akalan untuk laptop berspesifikasi rendah. Ketika menyiapkan server kompilasi otomatis (*headless CI/CD*) seperti GitHub Actions atau menyambungkan aplikasi mobile ke [arsitektur backend modern berbasis edge serverless](/id/blog/arsitektur-backend-modern-edge-serverless), Anda juga akan memakai metode *command-line* yang persis sama.

## Persiapan Prasyarat Sebelum Instalasi

Sebelum membuka terminal, unduh lima perangkat lunak dasar berikut. Semuanya gratis dan bersumber langsung dari repositori resmi:

- **Git:** Unduh dari situs resmi Git jika belum terpasang di komputer Anda. Flutter bergantung pada Git untuk mengunduh pembaruan dan mengelola versi SDK.
- **OpenJDK 17 atau 21 LTS:** Unduh melalui [Eclipse Temurin (Adoptium)](https://adoptium.net/){target="_blank"} atau Microsoft Build of OpenJDK. Pilih pemasang berformat `.msi` (Windows) atau `.pkg` (macOS) dan centang opsi pengaturan variabel `JAVA_HOME` otomatis saat instalasi berlangsung. Pengguna Linux atau macOS juga dapat memasangnya lewat manajer paket `apt` atau Homebrew.
- **Flutter SDK:** Unduh arsip zip terbaru dari halaman [instalasi manual Flutter](https://docs.flutter.dev/install/manual){target="_blank"}.
- **Android Command-line Tools:** Buka [halaman unduhan Android Studio](https://developer.android.com/studio){target="_blank"}, gulir ke bagian paling bawah menuju tabel **"Command line tools only"**, lalu unduh paket zip sesuai sistem operasi Anda.
- **Visual Studio Code:** Editor teks ringan tempat kita menulis kode Dart dan menjalankan *debugger*.

::note
Tim Flutter dan Google memperbarui target API Android secara berkala mengikuti aturan rilis tahunan Google Play Console. Selalu periksa kesesuaian versi `platforms` dan `build-tools` terbaru pada dokumentasi resmi sebelum mengeksekusi perintah instalasi di terminal.
::

## Cara Install Flutter Tanpa Android Studio di Tahun 2026

Panduan bertahap di bawah ini menggunakan contoh direktori `C:\Android` pada Windows. Pengguna Linux dan macOS dapat menyesuaikan lokasinya ke `~/Android`. Hindari menaruh SDK di dalam folder yang mengandung spasi atau membutuhkan hak akses administrator seperti `C:\Program Files`.

::steps
### Susun Struktur Folder SDK dengan Tepat

Buat folder induk `C:\Android`. Ekstrak arsip Flutter SDK ke dalamnya sehingga membentuk jalur `C:\Android\flutter` (Anda juga bebas menaruhnya di `C:\src\flutter` atau `~/development/flutter` asalkan konsisten saat mendaftarkan variabel `PATH`).

Selanjutnya, buat folder `C:\Android\sdk\cmdline-tools`. Ekstrak isi arsip *command-line tools* yang Anda unduh tadi. Di dalam arsip tersebut, terdapat folder bernama `cmdline-tools` yang langsung memuat folder `bin`, `lib`, dan berkas `source.properties`.

Ubah nama folder hasil ekstraksi tersebut menjadi `latest`, lalu letakkan di dalam `C:\Android\sdk\cmdline-tools\`. Hasil akhirnya wajib membentuk struktur direktori seperti di bawah ini:

- `C:\Android\flutter\bin\`
- `C:\Android\sdk\cmdline-tools\latest\bin\`
- `C:\Android\sdk\cmdline-tools\latest\lib\`

Jika folder `bin` berada langsung di bawah `cmdline-tools` tanpa perantara folder `latest`, `sdkmanager` akan berhenti bekerja dan memunculkan pesan galat `cmdline-tools component is missing`.

### Daftarkan Variabel ANDROID_HOME dan PATH

Kita perlu memberi tahu sistem operasi letak Flutter, Java, dan Android SDK. Buka **PowerShell** biasa (bukan sebagai Administrator), lalu jalankan blok perintah ini untuk menyimpan variabel di tingkat pengguna (*User*):

```powershell
[Environment]::SetEnvironmentVariable("ANDROID_HOME", "C:\Android\sdk", "User")

$p = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$p;C:\Android\flutter\bin;C:\Android\sdk\cmdline-tools\latest\bin;C:\Android\sdk\platform-tools", "User")
```

Apabila Anda belum mengatur `JAVA_HOME` saat memasang OpenJDK, daftarkan juga lokasinya menggunakan perintah `setx JAVA_HOME "C:\Program Files\Eclipse Adoptium\jdk-17..."` sesuai folder instalasi JDK di komputer Anda.

Bagi pengguna **macOS atau Linux**, buka berkas `~/.zshrc` atau `~/.bashrc` menggunakan editor teks, lalu tambahkan baris konfigurasi berikut di bagian paling bawah:

```bash
export ANDROID_HOME="$HOME/Android/sdk"
export JAVA_HOME="/path/to/jdk-17"
export PATH="$PATH:$HOME/Android/flutter/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools"
```

Tutup jendela PowerShell atau terminal Anda, lalu buka jendela baru agar variabel lingkungan yang baru disetel dimuat ulang. Uji keberhasilannya dengan menjalankan `flutter --version` dan `java -version`.

### Pasang Paket Esensial via sdkmanager

Sekarang kita akan mengunduh komponen kompilasi Android langsung dari terminal. Anda hanya memerlukan tiga paket utama: `platform-tools` (berisi ADB untuk komunikasi ke ponsel), `platforms` (kerangka kerja API Android), dan `build-tools` (perkakas perakit APK).

Jalankan perintah berikut di terminal:

```bash
sdkmanager --update
sdkmanager --install "platform-tools" "platforms;android-35" "build-tools;35.0.0"
```

Jika proyek Anda menargetkan Android 16, ganti angka `35` menjadi `36` (`"platforms;android-36"` dan `"build-tools;36.0.0"`). Komponen tambahan seperti NDK dan CMake tidak perlu diunduh sekarang karena Gradle akan mengunduhnya secara otomatis apabila ada *plugin* yang membutuhkannya saat kompilasi.

### Tautkan SDK ke Flutter dan Setujui Lisensi

Beritahukan lokasi tepat folder Android SDK kepada konfigurasi internal Flutter, lalu setujui seluruh klausul lisensi dari Google:

```bash
flutter config --android-sdk "C:\Android\sdk"
flutter doctor --android-licenses
```

Terminal akan menampilkan beberapa halaman persetujuan lisensi. Ketik `y` lalu tekan Enter berulang kali hingga seluruh lisensi disetujui. Setelah selesai, periksa kesehatan instalasi dengan perintah:

```bash
flutter doctor -v
```

Target utama kita adalah melihat tanda centang hijau `[✓]` pada bagian **Flutter**, **Android toolchain**, dan **VS Code**. Anda akan tetap melihat tanda seru `[!] Android Studio (not installed)`. Abaikan saja peringatan tersebut karena tanda itu hanya bersifat informatif dan sama sekali tidak menghalangi proses kompilasi aplikasi.

### Konfigurasi VS Code untuk Mulai Menulis Kode

Buka Visual Studio Code, masuk ke menu Extensions (`Ctrl+Shift+X`), lalu cari dan pasang ekstensi resmi **Flutter**. Ekstensi bahasa **Dart** akan ikut terpasang secara otomatis.

Tekan `Ctrl+Shift+P` (atau `F1`), ketik `Flutter: New Project`, pilih templat **Application**, dan tentukan folder penyimpanan proyek Anda. Begitu proyek terbuka, Anda siap merancang tampilan aplikasi dengan berpegang pada [prinsip gaya desain grafis dan UI modern](/id/blog/mengenal-jenis-gaya-desain-grafis-dan-ui) agar produk buatan Anda tampil rapi dan fungsional.
::

::warning
Jangan pernah menyalin perintah `setx path "C:\Android\tools\bin;..."` dari artikel tutorial lawas. Perintah `setx path` secara langsung menimpa seluruh daftar `PATH` pengguna yang sudah ada dan memotongnya hingga batas 1024 karakter. Akibatnya, perintah penting lain seperti Git, Node.js, atau Python mendadak rusak dan tidak dikenali terminal. Gunakan metode `[Environment]::SetEnvironmentVariable` di PowerShell seperti pada Langkah 2 agar jalur baru ditambahkan dengan aman di belakang jalur lama.
::

## Alternatif Cepat: Skrip Otomasi PowerShell dan Bash

Jika Anda enggan membuat folder dan mengekstrak arsip zip satu per satu lewat antarmuka berkas, gunakan skrip penyedia (*provisioning*) sekali jalan. Skrip ini juga sangat berguna saat menyiapkan *runner* CI/CD tanpa antarmuka grafis.

Salin dan tempelkan URL unduhan terbaru dari halaman resmi Android Developer ke dalam variabel `$downloadUrl`, lalu jalankan skrip PowerShell berikut di Windows:

```powershell
$sdkDir = "C:\Android\sdk"
$cmdlineZip = "$env:TEMP\cmdline-tools.zip"
$downloadUrl = "https://dl.google.com/android/repository/commandlinetools-win-latest.zip"

New-Item -ItemType Directory -Force -Path "$sdkDir\cmdline-tools" | Out-Null
Invoke-WebRequest -Uri $downloadUrl -OutFile $cmdlineZip
Expand-Archive -Path $cmdlineZip -DestinationPath "$sdkDir\cmdline-tools" -Force
Rename-Item -Path "$sdkDir\cmdline-tools\cmdline-tools" -NewName "latest"
Remove-Item $cmdlineZip
```

Pengguna Linux dan macOS dapat menjalankan ekuivalen perintahnya menggunakan Bash:

```bash
SDK_DIR="$HOME/Android/sdk"
DOWNLOAD_URL="https://dl.google.com/android/repository/commandlinetools-linux-latest.zip"

mkdir -p "$SDK_DIR/cmdline-tools"
curl -o /tmp/cmdline-tools.zip "$DOWNLOAD_URL"
unzip -q /tmp/cmdline-tools.zip -d "$SDK_DIR/cmdline-tools"
mv "$SDK_DIR/cmdline-tools/cmdline-tools" "$SDK_DIR/cmdline-tools/latest"
rm /tmp/cmdline-tools.zip
```

Setelah skrip selesai dieksekusi, Anda tinggal melanjutkan ke tahap pendaftaran `ANDROID_HOME` dan eksekusi `sdkmanager`.

## Menguji Aplikasi Langsung di Ponsel Fisik

Memakai ponsel Android fisik sebagai perangkat uji utama adalah kunci penghematan RAM paling efektif. Laptop Anda hanya bertugas mengompilasi kode, sedangkan beban pemrosesan grafis aplikasi ditanggung sepenuhnya oleh prosesor ponsel.

::steps
### Aktifkan Opsi Pengembang di Ponsel

Buka menu **Setelan > Tentang Ponsel**, lalu ketuk bagian **Nomor Build** (*Build Number*) sebanyak tujuh kali berturut-turut hingga muncul notifikasi bahwa Anda telah menjadi pengembang. Pada perangkat Xiaomi, Redmi, atau POCO, ketuk pada baris **Versi MIUI** atau **Versi Xiaomi HyperOS**.

### Nyalakan USB Debugging

Kembali ke menu utama Setelan, masuk ke **Sistem > Opsi Pengembang** (atau **Setelan Tambahan > Opsi Pengembang**). Geser tombol **Proses Debug USB** (*USB Debugging*) ke posisi aktif.

Khusus pengguna Xiaomi/HyperOS, Anda wajib mengaktifkan dua tombol tambahan yang berada tepat di bawahnya: **Instal via USB** dan **Proses Debug USB (Setelan Keamanan)**. Tanpa kedua opsi tersebut, VS Code akan gagal memasang APK ke ponsel saat Anda menjalankan aplikasi.

### Hubungkan via Kabel Data atau Wi-Fi

Tancapkan ponsel ke laptop menggunakan kabel data yang mendukung transfer berkas (bukan kabel pengisi daya biasa). Ketika layar ponsel memunculkan jendela konfirmasi "Izinkan proses debug USB?", centang kotak **Selalu izinkan dari komputer ini**, kemudian ketuk **Izinkan**.

Periksa koneksi dari terminal VS Code:

```bash
adb devices
flutter devices
```

Pastikan nomor seri ponsel Anda muncul dengan status `device`. Apabila tertulis `unauthorized`, cabut kabel dan ulangi persetujuan dialog izin di layar ponsel. Setelah terdeteksi, tekan `F5` di VS Code atau ketik `flutter run` untuk meluncurkan aplikasi.
::

### Debugging Nirkabel lewat Wi-Fi (Android 11+)

Jika port USB laptop Anda longgar atau Anda tidak suka direpotkan oleh kabel di meja kerja, manfaatkan fitur *Wireless Debugging* bawaan Android 11 ke atas. Pastikan laptop dan ponsel terhubung ke jaringan Wi-Fi yang sama.

1. Masuk ke **Opsi Pengembang > Proses Debug Nirkabel**, lalu aktifkan fiturnya.
2. Ketuk menu **Sambungkan perangkat dengan kode penyambungan** (*Pair device with pairing code*). Layar ponsel akan menampilkan alamat IP, port penyambungan, dan enam digit kode angka.
3. Jalankan perintah penyambungan di terminal sesuai IP dan port yang tertera di layar ponsel, lalu masukkan enam digit kode saat diminta:

```bash
adb pair 192.168.1.15:39123
```

4. Setelah statusnya berhasil terhubung (*Successfully paired*), lihat halaman utama **Proses Debug Nirkabel** di ponsel. Catat alamat IP dan port baru yang tertera di bawah nama perangkat Anda (port ini berbeda dengan port saat *pairing* tadi), lalu hubungkan:

```bash
adb connect 192.168.1.15:41555
```

Kini ponsel Anda siap menerima *hot reload* dari VS Code tanpa kabel USB.

::tip
Aktifkan opsi **Tetap terjaga** (*Stay awake*) di dalam menu Opsi Pengembang ponsel. Fitur ini menjaga layar ponsel tetap menyala selama terhubung ke komputer, sehingga Anda tidak perlu membuka kunci layar berulang kali setiap kali menguji perubahan antarmuka.
::

## Optimasi Gradle untuk Laptop RAM 8 GB

Salah satu keluhan terbesar saat mempraktikkan **cara install Flutter tanpa Android Studio di tahun 2026** pada laptop ber-RAM 8 GB adalah proses kompilasi pertama yang menguras memori hingga komputer macet (*freeze*). Penyebabnya bukan VS Code, melainkan proses latar belakang **Gradle Daemon** yang mengambil alokasi memori terlalu agresif secara bawaan.

Anda bisa membatasi pemakaian RAM Gradle dengan membuat atau menyunting berkas konfigurasi global di `C:\Users\<NamaUser>\.gradle\gradle.properties` (Windows) atau `~/.gradle/gradle.properties` (macOS/Linux). Masukkan tiga baris pengaturan berikut:

```ini
org.gradle.jvmargs=-Xmx2048m -XX:MaxMetaspaceSize=512m
org.gradle.parallel=true
org.gradle.daemon=true
```

Konfigurasi `-Xmx2048m` membatasi mesin virtual Java untuk Gradle agar tidak menggunakan RAM lebih dari 2 GB. Dikombinasikan dengan VS Code yang hanya memakan sekitar 300 hingga 600 MB RAM, laptop ber-RAM 8 GB dengan prosesor sekelas Intel Core i3 atau Ryzen 3 tetap leluasa membuka peramban web sambil mengompilasi proyek.

## Membuat Emulator Tanpa Android Studio (Opsional)

Bagaimana jika Anda tetap membutuhkan emulator Android tetapi enggan memasang Android Studio? Anda tetap bisa mengunduh *system image* dan merakit Android Virtual Device (AVD) murni lewat terminal.

Namun, ingat kembali tujuan awal kita menghemat ruang penyimpanan dan memori. Mengunduh *system image* dan menyalakan emulator akan memakan ruang penyimpanan serta RAM tambahan yang cukup besar. Jika spesifikasi komputer Anda memadai, jalankan perintah ini:

```bash
sdkmanager "emulator" "system-images;android-35;google_apis;x86_64"
avdmanager create avd -n test_emu -k "system-images;android-35;google_apis;x86_64"
```

Bagi pengguna Mac dengan prosesor Apple Silicon, ganti arsitektur `x86_64` pada perintah di atas menjadi `arm64-v8a`. Setelah AVD berhasil dibuat, Anda dapat menyalakannya kapan saja lewat perintah `emulator -avd test_emu` (atau `flutter emulators --launch test_emu`) maupun memilihnya langsung dari sudut kanan bawah jendela VS Code.

::tip
Sedang belajar dasar pemrograman Dart, menyusun *layout widget*, atau melatih manajemen *state* tanpa membawa ponsel? Jalankan saja proyek Anda sebagai aplikasi web atau desktop lewat perintah `flutter run -d chrome` atau `flutter run -d windows`. Keduanya berjalan jauh lebih ringan daripada emulator Android.
::

## Kompromi dan Batasan yang Perlu Anda Ketahui

Memangkas Android Studio memberikan lingkungan kerja yang gesit, tetapi ada tiga kompromi teknis yang harus Anda pahami sejak awal:

- **Manajemen SDK Sepenuhnya lewat Teks:** Anda tidak memiliki jendela grafis *SDK Manager* untuk mencentang versi Android. Untuk melihat daftar paket yang terpasang, Anda harus mengetik `sdkmanager --list_installed`, dan untuk menghapusnya Anda memakai `sdkmanager --uninstall "<nama_paket>"`.
- **Absennya Perkakas Profiling Native:** Untuk kebutuhan inspeksi pohon *widget* dan pemantauan performa aplikasi sehari-hari, **Flutter DevTools** yang terintegrasi di VS Code sudah sangat memadai. Namun, Anda kehilangan akses ke profiler memori tingkat *native* Android dan *App Inspection* bawaan Android Studio.
- **Penyuntingan Kode Kotlin/Java Lebih Minim:** Apabila proyek Anda sering memodifikasi folder `android/` untuk menulis *MethodChannel* atau merombak skrip konfigurasi Gradle yang kompleks, fitur pelengkap kode (*auto-complete*) Kotlin di VS Code tidak selengkap milik Android Studio.

Bagi pengembang yang fokus membangun antarmuka lintas platform atau para desainer yang sedang mendalami [panduan karier UI/UX designer dan produk digital](/id/blog/panduan-karier-ui-ux-designer) dan ingin memvalidasi desainnya langsung ke bentuk kode Flutter, ketiga batasan di atas hampir tidak pernah menjadi penghambat.

## Mengatasi Galat yang Paling Sering Muncul

Jika proses instalasi atau pemeriksaan `flutter doctor` Anda menemui jalan buntu, cocokkan pesan galat di terminal Anda dengan tabel solusi berikut:

| Pesan Galat di Terminal | Penyebab Utama | Solusi Perbaikan |
| :--- | :--- | :--- |
| `cmdline-tools component is missing` | Isi zip diekstrak langsung ke `cmdline-tools` tanpa subfolder `latest`. | Pastikan berkas `sdkmanager` berada tepat di jalur `.../cmdline-tools/latest/bin/sdkmanager`. |
| `Android license status unknown` | Variabel `JAVA_HOME` kosong atau memakai versi JDK yang tidak kompatibel (seperti JDK 23). | Pasang OpenJDK 17 atau 21 LTS, lalu pastikan perintah `java -version` berjalan valid di terminal. |
| `Unable to locate Android SDK` | Variabel `ANDROID_HOME` terabaikan sehingga Flutter mencari ke folder bawaan `AppData`. | Jalankan perintah `flutter config --android-sdk "<lokasi_sdk>"`. |
| `UnsupportedClassVersionError` | Sistem masih memanggil JDK 8 atau JDK 11 lama yang tertinggal di komputer. | Arahkan Flutter secara eksplisit ke JDK baru dengan `flutter config --jdk-dir "<path_jdk_17>"`. |
| Perangkat ponsel tidak terdeteksi | Mode USB Debugging belum aktif, atau `platform-tools` belum masuk ke `PATH`. | Jalankan `adb devices` di terminal dan setujui jendela otorisasi di layar ponsel. |
