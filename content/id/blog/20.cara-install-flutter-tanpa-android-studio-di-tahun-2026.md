Anda bisa install Flutter tanpa Android Studio. Yang dibutuhkan Flutter untuk membangun aplikasi Android hanya tiga hal: Flutter SDK, JDK, dan Android SDK yang dipasang lewat command-line tools. Kode ditulis di VS Code. Paket command-line tools berukuran sekitar 156 MB, sedangkan installer Android Studio 1,5 GB.

![Ilustrasi install Flutter tanpa Android Studio memakai terminal dan VS Code](/article/flutter-tanpa-android-studio.webp)

Tulisan ini memperbarui [panduan lama karya Ihwan di Easyread](https://medium.easyread.co/instalasi-flutter-tanpa-android-studio-2a0876302a68){target="_blank"} (2019, direvisi 2020) yang dulu menolong banyak pemilik laptop ber-SSD 120 GB. Idenya masih sama. Hampir semua detail teknisnya sudah berubah, dan beberapa perintah lama malah berbahaya jika disalin hari ini.

## Apa yang Berubah Sejak Panduan Versi 2020

Panduan lama ditulis untuk Flutter 1.12, JDK 8, dan Android 29. Per Oktober 2026, versi stabil terbaru adalah Flutter 3.47.1 dengan Dart 3.13.1, dan dokumentasi resminya meminta Android SDK Platform API 36.

| Komponen | Panduan 2020 | Kondisi 2026 |
| :--- | :--- | :--- |
| **Flutter** | 1.12.13 | 3.47.1 (Dart 3.13.1) |
| **JDK** | OpenJDK 8 | JDK 17 atau lebih baru |
| **Platform Android** | `android-29` | `android-36` |
| **Folder tools** | `C:\Android\tools\bin` | `sdk\cmdline-tools\latest\bin` |
| **Variabel SDK** | `ANDROID_SDK_ROOT` | `ANDROID_HOME` |
| **Trik `--sdk_root`** | Wajib di tiap perintah | Tidak perlu jika struktur folder benar |

Dua perubahan paling sering menjebak. Pertama, folder `tools` sudah lama diganti `cmdline-tools`, dan `sdkmanager` hanya mau bekerja normal jika berada di dalam subfolder bernama `latest`. Kedua, `ANDROID_SDK_ROOT` sudah usang. Gunakan `ANDROID_HOME`, dan arahkan ke folder SDK, bukan ke folder induknya.

## Yang Perlu Disiapkan Sebelum Mulai

Siapkan empat unduhan berikut. Semuanya gratis dan resmi.

- **Flutter SDK** dari halaman [instalasi manual Flutter](https://docs.flutter.dev/install/manual).
- **Command-line tools** dari bagian "Command line tools only" di [halaman unduhan Android Studio](https://developer.android.com/studio). Saat tulisan ini dibuat, nama berkasnya `commandlinetools-win-15859902_latest.zip` untuk Windows.
- **JDK 17 atau lebih baru**, misalnya [Eclipse Temurin](https://adoptium.net/). Pilih installer `.msi` atau `.pkg` supaya `JAVA_HOME` terisi otomatis.
- **VS Code** sebagai editor.

Anda juga butuh Git, karena Flutter memakainya untuk memperbarui diri.

::note
Nomor versi di artikel ini adalah kondisi Oktober 2026. Flutter merilis versi stabil kira-kira tiap tiga bulan, jadi selalu cocokkan API level dengan halaman [Set up Android development](https://docs.flutter.dev/platform-integration/android/setup) sebelum menyalin perintah.
::

## Langkah Install Flutter dan Android SDK

Contoh di bawah memakai Windows dengan folder kerja `C:\Android`. Pengguna macOS dan Linux cukup mengganti lokasinya, misalnya `~/Android`. Hindari path yang mengandung spasi seperti `C:\Program Files`, karena Flutter sering gagal di sana.

::steps
### Susun Struktur Folder dengan Benar

Ekstrak Flutter SDK ke `C:\Android\flutter`. Lalu ekstrak command-line tools. Hasil ekstraknya adalah folder bernama `cmdline-tools` yang langsung berisi `bin` dan `lib`. Isi itulah yang harus Anda pindahkan ke dalam subfolder `latest`.

```text
C:\Android
├── flutter
│   └── bin
└── sdk
    └── cmdline-tools
        └── latest
            ├── bin
            └── lib
```

Jika `bin` berada langsung di bawah `cmdline-tools` tanpa `latest`, `sdkmanager` akan menolak dengan pesan "Could not determine SDK root". Inilah sumber galat yang dulu diakali dengan parameter `--sdk_root`.

### Atur ANDROID_HOME dan PATH

Buka PowerShell, lalu jalankan dua perintah ini.

```powershell
[Environment]::SetEnvironmentVariable("ANDROID_HOME", "C:\Android\sdk", "User")

$p = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$p;C:\Android\flutter\bin;C:\Android\sdk\cmdline-tools\latest\bin;C:\Android\sdk\platform-tools", "User")
```

Di macOS atau Linux, tambahkan baris berikut ke `~/.zshrc` atau `~/.bashrc`.

```bash
export ANDROID_HOME="$HOME/Android/sdk"
export PATH="$PATH:$HOME/Android/flutter/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools"
```

Tutup terminal, buka yang baru, lalu periksa dengan `flutter --version` dan `java -version`.

### Pasang Paket Android SDK

Cukup tiga paket untuk bisa membangun dan menjalankan aplikasi di ponsel.

```bash
sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"
```

Pengguna macOS dan Linux boleh memakai tanda petik tunggal. NDK dan CMake tidak perlu dipasang manual. Gradle mengunduhnya sendiri saat build pertama membutuhkannya, asalkan lisensi sudah disetujui.

### Setujui Lisensi dan Jalankan Flutter Doctor

```bash
flutter config --android-sdk "C:\Android\sdk"
flutter doctor --android-licenses
flutter doctor
```

Jawab `y` untuk setiap lisensi. Keluhan lama soal lisensi yang sulit disetujui sudah tidak muncul selama JDK Anda versi 17 ke atas. `flutter doctor` akan memberi tanda centang pada "Android toolchain" dan tanda peringatan pada "Android Studio (not installed)". Peringatan itu memang diharapkan dan boleh diabaikan.

### Siapkan VS Code dan Jalankan Proyek

Pasang ekstensi **Flutter** di VS Code. Ekstensi Dart ikut terpasang otomatis. Tekan `F1`, pilih `Flutter: New Project`, lalu hubungkan ponsel Android yang sudah mengaktifkan USB debugging. Cara menyiapkan ponselnya dibahas di bagian berikutnya.

```bash
flutter devices
flutter run
```

Tekan `F5` di VS Code jika Anda ingin sesi debug dengan breakpoint dan hot reload.
::

::warning
Jangan salin perintah `setx path "C:\Android\tools\bin;..."` dari panduan lama. Perintah itu menimpa seluruh isi PATH pengguna, sehingga Git, Node, Python, dan alat lain mendadak tidak dikenali terminal. Dua perintah PowerShell di atas menambahkan path baru tanpa menghapus yang sudah ada.
::

## Menguji Langsung di Ponsel Android

Panduan ini memakai ponsel Android sebagai perangkat uji utama. Tidak ada emulator yang perlu diunduh, dan RAM laptop tetap lega. Ponsel hanya perlu disiapkan satu kali lewat mode pengembang (Developer options).

::steps
### Aktifkan Mode Pengembang

Buka **Setelan > Tentang ponsel**, lalu ketuk **Nomor build** tujuh kali sampai muncul pesan "Anda sekarang adalah pengembang". Di ponsel Xiaomi, Redmi, dan POCO, yang diketuk adalah **Versi MIUI** atau **Versi OS**. Nama menunya sedikit berbeda di tiap merek, tetapi letaknya selalu di halaman informasi perangkat.

### Nyalakan USB Debugging

Kembali ke Setelan, buka **Opsi pengembang** (biasanya di bawah **Sistem** atau **Setelan tambahan**), lalu aktifkan **Proses debug USB**. Pengguna Xiaomi perlu mengaktifkan juga **Instal via USB**. Tanpa opsi itu, `flutter run` berhenti saat memasang aplikasi.

### Hubungkan Ponsel ke Laptop

Pakai kabel data, bukan kabel yang hanya bisa mengisi daya. Saat ponsel menampilkan dialog "Izinkan proses debug USB?", centang **Selalu izinkan dari komputer ini**, lalu ketuk **Izinkan**. Di Windows, sebagian merek membutuhkan driver USB dari pabrikannya.

### Pastikan Flutter Mengenali Ponsel

```bash
adb devices
flutter devices
```

Ponsel harus muncul dengan status `device`. Status `unauthorized` berarti dialog izin di ponsel belum disetujui. Setelah itu, jalankan `flutter run` dari folder proyek. Build pertama memakan beberapa menit karena Gradle mengunduh dependensi.
::

### Debugging Tanpa Kabel lewat Wi-Fi

Android 11 ke atas mendukung proses debug nirkabel. Laptop dan ponsel harus berada di jaringan Wi-Fi yang sama. Aktifkan **Proses debug nirkabel** di Opsi pengembang, ketuk **Sambungkan perangkat dengan kode penyambungan**, lalu masukkan alamat dan kode yang tampil.

```bash
adb pair 192.168.1.10:37123
adb connect 192.168.1.10:41234
```

Port untuk `pair` dan `connect` berbeda. Keduanya tertera di layar ponsel. Koneksi kabel tetap lebih stabil untuk sesi kerja yang panjang.

::tip
Aktifkan **Tetap terjaga** di Opsi pengembang agar layar tidak mati selama ponsel terhubung. Hot reload terasa jauh lebih nyaman ketika layar tidak perlu dibuka kuncinya berulang kali.
::

## Emulator Tanpa Android Studio, Perlu atau Tidak

Emulator tetap bisa dibuat dari terminal. Tetapi pertimbangkan dulu tujuan awalnya, yaitu menghemat storage dan RAM. System image Android berukuran besar, dan emulator memakan memori yang justru ingin Anda hemat.

Untuk laptop dengan RAM 8 GB, ponsel fisik hampir selalu pilihan yang lebih nyaman. Jika tetap butuh emulator, ini perintahnya.

```bash
sdkmanager "emulator" "system-images;android-36;google_apis;x86_64"
avdmanager create avd -n pixel -k "system-images;android-36;google_apis;x86_64" -d pixel_7
flutter emulators --launch pixel
```

Pengguna Mac dengan chip Apple Silicon mengganti `x86_64` dengan `arm64-v8a`.

::tip
Belum punya ponsel Android untuk uji coba? Jalankan `flutter run -d chrome` atau `flutter run -d windows`. Anda tetap bisa belajar widget dan state management tanpa emulator sama sekali.
::

## Kompromi yang Harus Anda Terima

Cara ini bukan tanpa harga. Ada tiga hal yang hilang dibanding memakai Android Studio.

- **Tidak ada antarmuka grafis untuk SDK.** Memperbarui paket berarti menjalankan `sdkmanager --update` sendiri, dan Anda harus tahu nama paketnya.
- **Tidak ada alat khusus Android.** Layout Inspector, profiler native, dan editor Gradle bawaan tidak tersedia. Untuk aplikasi Flutter murni, DevTools dari Flutter sudah mencukupi.
- **Kode native lebih repot disunting.** Jika proyek Anda banyak menyentuh Kotlin atau berkas Gradle, dukungan VS Code terasa jauh lebih tipis.

Bagi pemula yang baru belajar Flutter, ketiganya jarang terasa. Bagi tim yang merawat plugin native, ceritanya berbeda.

## Mengatasi Galat yang Paling Sering Muncul

| Pesan galat | Penyebab | Perbaikan |
| :--- | :--- | :--- |
| `Could not determine SDK root` | `bin` tidak berada di dalam `cmdline-tools\latest` | Perbaiki struktur folder sesuai langkah pertama |
| `Unable to locate Android SDK` | Flutter belum tahu lokasi SDK | Jalankan `flutter config --android-sdk` |
| `UnsupportedClassVersionError` | JDK terlalu lama, biasanya JDK 8 | Pasang JDK 17 ke atas, periksa `JAVA_HOME` |
| `sdkmanager is not recognized` | PATH belum dimuat ulang | Tutup dan buka terminal baru |
| Ponsel tidak muncul di `flutter devices` | USB debugging mati atau driver OEM belum ada | Aktifkan Developer options, pasang driver USB |

## Panduan Pengambilan Keputusan

::conclusion
Pilih jalur sesuai kondisi perangkat dan jenis pekerjaan Anda:

- **Pakai cara ini** jika storage Anda sempit, RAM 8 GB atau kurang, dan Anda menulis aplikasi Flutter murni di VS Code dengan ponsel fisik sebagai perangkat uji.
- **Tambahkan emulator lewat terminal** hanya jika Anda perlu menguji versi Android atau ukuran layar yang tidak Anda miliki.
- **Pasang Android Studio** jika pekerjaan Anda rutin menyentuh kode Kotlin, konfigurasi Gradle yang rumit, atau profiling native. Waktu yang terbuang karena alat yang kurang lebih mahal daripada beberapa gigabita storage.

Apa pun pilihannya, jalankan `flutter doctor` setiap selesai `flutter upgrade`. API level yang diminta Flutter naik dari waktu ke waktu.
::

::faq
::faq-item{question="Apakah Flutter benar-benar bisa berjalan tanpa Android Studio?"}
Bisa. Flutter hanya memerlukan Android SDK, JDK, dan Flutter SDK. Android Studio sekadar cara paling mudah memasang Android SDK. Peringatan "Android Studio (not installed)" di `flutter doctor` tidak menghalangi build.
::
::faq-item{question="JDK versi berapa yang dipakai Flutter saat ini?"}
Gunakan JDK 17 atau lebih baru. JDK 8 dari panduan lama tidak lagi bisa menjalankan Gradle dan `sdkmanager` versi sekarang. Jika Anda punya beberapa JDK, arahkan Flutter dengan `flutter config --jdk-dir`.
::
::faq-item{question="Apakah ANDROID_SDK_ROOT masih perlu diatur?"}
Tidak. Variabel itu sudah usang. Cukup atur `ANDROID_HOME` ke folder SDK, lalu jalankan `flutter config --android-sdk` supaya Flutter menyimpan lokasinya.
::
::faq-item{question="Bisakah saya build APK rilis dengan cara ini?"}
Bisa. Perintah `flutter build apk` dan `flutter build appbundle` berjalan sepenuhnya dari terminal. Penandatanganan aplikasi diatur lewat berkas `key.properties` dan Gradle, tanpa perlu IDE.
::
::faq-item{question="Bagaimana cara memperbarui Android SDK tanpa SDK Manager grafis?"}
Jalankan `sdkmanager --update` untuk memperbarui semua paket terpasang, dan `sdkmanager --list_installed` untuk melihat isinya. Paket platform lama bisa dihapus dengan `sdkmanager --uninstall` agar storage tetap lega.
::
