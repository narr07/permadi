**Panduan membangun antarmuka cepat dengan Nuxt UI** berfokus pada pemanfaatan modul pustaka komponen resmi (`@nuxt/ui`) berbasis Reka UI, Tailwind CSS v4, dan Tailwind Variants. Pustaka ini mengotomatiskan integrasi ikon, tipografi, mode gelap, serta aksesibilitas WAI-ARIA pada aplikasi Nuxt 3 dan Vue, sehingga Anda dapat merilis antarmuka produksi tanpa merakit logika dasar dari nol.

Merakit komponen interaktif seperti modal, *dropdown*, tabel data, dan validasi formulir dari awal sering menguras jam kerja rekayasa perangkat lunak. Waktu yang seharusnya Anda alokasikan untuk menggarap logika bisnis justru habis untuk merawat kode CSS yang membengkak, mengatur manajemen fokus *keyboard*, dan menambal celah kompatibilitas antarperamban.

Pustaka resmi ekosistem Nuxt hadir untuk memangkas jalur kerja tersebut. Jika Anda baru mendalami ekosistem ini, pelajari dulu fondasi [mengenal Nuxt JS](/id/blog/mengenal-nuxt-js-framework-vue-ssr-ssg) agar konsep *Server-Side Rendering* (SSR) dan struktur direktorinya tergambar jelas sebelum masuk ke lapisan visual.

## Mengapa Mengikuti Panduan Membangun Antarmuka Cepat dengan Nuxt UI?

Sejak pembaruan arsitektur Nuxt UI v3 pada Maret 2025, pustaka ini menanggalkan ketergantungan lama pada Headless UI dan beralih penuh ke **Reka UI** serta mesin **Tailwind CSS v4**. Perubahan fondasi ini melompatkan kecepatan kompilasi sekaligus menyederhanakan konfigurasi bagi *frontend engineer*.

Empat keunggulan teknis membuat Nuxt UI sangat tangguh di lingkungan produksi:

1. **Fondasi Aksesibilitas Reka UI**: Primitif Reka UI langsung mengelola seluruh navigasi *keyboard*, penguncian fokus (*focus trap*), dan atribut WAI-ARIA. Anda tidak perlu lagi menulis *event listener* manual untuk tombol `Escape`, menghitung posisi *popover* di tepi layar, atau mengatur navigasi panah pada komponen menu.
2. **Arsitektur CSS-First Tailwind v4**: Integrasi dengan mesin baru Tailwind CSS v4 memangkas waktu kompilasi bertahap (*incremental builds*) hingga 5 sampai 100 kali lebih cepat. Mesin ini juga menghasilkan *bundle* CSS akhir yang jauh lebih ramping.
3. **Otomatisasi Modul Inti**: Saat Anda memasang `@nuxt/ui`, sistem secara otomatis mendaftarkan `@nuxt/icon`, `@nuxt/fonts`, dan `@nuxtjs/color-mode` di balik layar. Anda langsung mendapat akses ke ratusan ribu ikon Iconify, manajemen *font* lokal maupun web secara otomatis, serta fitur *dark mode* tanpa instalasi terpisah.
4. **Dukungan Universal Vue**: Meski lahir dari ekosistem Nuxt, versi modern pustaka ini tidak lagi terkunci pada Nuxt SSR. Anda dapat memakainya langsung di aplikasi Vue murni berbasis Vite maupun di dalam tumpukan Inertia.js bersama Laravel atau AdonisJS.

### Perbandingan Nuxt UI, Shadcn Vue, dan Vuetify

Memilih pustaka komponen adalah keputusan arsitektur jangka panjang yang menentukan kecepatan kerja tim. Tabel berikut memetakan posisi Nuxt UI dibandingkan dua alternatif populer di ekosistem Vue 3:

| Parameter Teknis | Nuxt UI (v3+) | Shadcn Vue | Vuetify 3 |
| :--- | :--- | :--- | :--- |
| **Mesin Styling Utama** | Tailwind CSS v4 & Tailwind Variants | Tailwind CSS | SASS / Material CSS |
| **Primitif Aksesibilitas** | Reka UI | Reka UI | Mesin Internal Vuetify |
| **Model Distribusi** | Modul npm terpusat (`@nuxt/ui`) | Salin-tempel kode ke repositori lokal | Paket npm monolitik |
| **Beban Pemeliharaan** | Rendah (pembaruan via *package manager*) | Tinggi (wajib merawat kode komponen sendiri) | Sedang (terikat aturan Material Design) |
| **Integrasi Ekosistem Nuxt** | Native (*auto-import* penuh, Nuxt DevTools) | Manual via konfigurasi modul | Membutuhkan modul jembatan tambahan |

Vuetify cocok bila tim Anda terikat ketat pada pedoman Material Design, tetapi ukuran *runtime*-nya relatif berat dan kustomisasi di luar pakem Material cukup rumit. Shadcn Vue menawarkan kendali penuh karena menyalin kodenya langsung ke proyek Anda, namun tim Anda harus menanggung beban pemeliharaan ratusan baris kode primitif setiap kali ada pembaruan. Nuxt UI mengambil jalan tengah terbaik: komponen dikelola sebagai dependensi yang bersih, sementara setiap bagiannya tetap terbuka untuk Anda ubah lewat API *Tailwind Variants*.

## Cara Install Nuxt UI dan Konfigurasi Awal Proyek

Cara install Nuxt UI pada proyek Nuxt 3 kini jauh lebih ringkas berkat arsitektur *CSS-first*. Anda tidak lagi berurusan dengan file konfigurasi Tailwind yang panjang. Ikuti urutan langkah berikut untuk menyiapkan fondasi aplikasi yang bersih.

::steps
### Pasang Paket Nuxt UI dan Tailwind CSS

Jalankan perintah instalasi melalui terminal di direktori proyek Nuxt Anda. Jika ingin memulai dari proyek kosong, Anda juga bisa menjalankan perintah inisialisasi `npx nuxi@latest init my-app -t ui`.

```bash
pnpm add @nuxt/ui tailwindcss
```

### Daftarkan Modul di Konfigurasi Nuxt

Buka file `nuxt.config.ts`, masukkan `@nuxt/ui` ke dalam daftar modul, lalu arahkan properti `css` ke file lembar gaya utama Anda.

```ts
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css']
})
```

### Deklarasikan Direktif CSS-First

Buat file `assets/css/main.css` dan tambahkan dua baris impor berikut. Anda tidak perlu lagi membuat file `tailwind.config.js` seperti pada versi lawas karena Tailwind CSS v4 membaca konfigurasi langsung dari file CSS.

```css
@import "tailwindcss";
@import "@nuxt/ui";
```

### Bungkus Aplikasi dengan Komponen UApp

Buka file `app.vue` dan bungkus seluruh tata letak menggunakan komponen `<UApp>`. Komponen akar ini wajib ada karena bertugas menyediakan konteks global untuk *Toast*, *Tooltip*, *Modal*, dan token tema dinamis.

```vue
<template>
  <UApp>
    <NuxtLayout>
      <NuxtPage />
    </NuxtLayout>
  </UApp>
</template>
```
::

::warning
Jangan menginstal atau mendaftarkan `@nuxt/icon`, `@nuxt/fonts`, dan `@nuxtjs/color-mode` secara terpisah di dalam array `modules` pada `nuxt.config.ts`. Duplikasi modul akan memicu konflik injeksi *style* dan membengkakkan ukuran *build*. Atur konfigurasi ketiganya langsung melalui properti tingkat akar di `nuxt.config.ts`.
::

## Kustomisasi Tema dan Sistem Desain di App Config

Desainer antarmuka sering khawatir penggunaan pustaka komponen siap pakai akan membuat tampilan situs terlihat seragam atau kaku. Untuk menghindari kesan generik tersebut, Anda dapat menyelaraskan token visual dengan prinsip dasar [ragam gaya desain grafis dan UI modern](/id/blog/mengenal-jenis-gaya-desain-grafis-dan-ui) langsung melalui file `app.config.ts`.

Nuxt UI menggunakan pendekatan warna semantik dan arsitektur *slots* dari Tailwind Variants. Setiap komponen kompleks dipecah menjadi beberapa bagian (*slots*) seperti `root`, `base`, `header`, `body`, dan `footer`. Anda cukup memetakan peran warna seperti `primary` dan `neutral` ke palet warna Tailwind serta mengubah kelas spesifik pada *slot* yang diinginkan tanpa menyentuh variabel CSS mentah:

```ts
export default defineAppConfig({
  ui: {
    colors: {
      primary: 'indigo',
      neutral: 'slate'
    },
    button: {
      slots: {
        base: 'font-semibold rounded-lg transition-transform active:scale-95'
      }
    },
    card: {
      slots: {
        root: 'rounded-xl shadow-sm border border-slate-200 dark:border-slate-800'
      }
    }
  }
})
```

Konfigurasi di atas secara otomatis mengubah seluruh warna utama komponen menjadi *indigo*, warna latar netral menjadi *slate*, serta menyuntikkan efek tekan halus pada semua tombol `<UButton>` di seluruh aplikasi. Perubahan ini bersifat reaktif dan langsung beradaptasi pada mode terang maupun mode gelap.

Jika Anda hanya perlu mengubah tampilan satu komponen di halaman tertentu tanpa memengaruhi standar global, gunakan properti `:ui` langsung pada elemen tersebut. Mesin penggabung kelas internal Nuxt UI akan menimpa kelas bawaan secara bersih tanpa konflik spesifisitas CSS.

::tip
Agar fitur *autocomplete* Tailwind CSS IntelliSense di VS Code tetap mengenali kelas di dalam `app.config.ts` dan properti `ui`, tambahkan pengaturan berikut pada file `.vscode/settings.json` proyek Anda:
::

```json
{
  "tailwindCSS.classAttributes": ["class", "ui"],
  "tailwindCSS.classFunctions": ["defineAppConfig"]
}
```

## Tutorial Nuxt UI: Merakit Form Interaktif dengan Validasi Zod

Kekuatan utama dari panduan membangun antarmuka cepat dengan Nuxt UI terlihat jelas saat kita menangani formulir input data. Biasanya, membuat satu form masuk atau pendaftaran membutuhkan manajemen *state* pesan kesalahan, *styling* kondisi gagal, pemasangan ikon input, hingga sistem notifikasi pop-up yang memakan ratusan baris kode.

Berikut adalah implementasi form autentikasi lengkap menggunakan *Nuxt 3 UI components* yang menggabungkan `<UForm>`, skema validasi **Zod**, dan *composable* `useToast()` tanpa menulis satu baris pun CSS kustom:

```vue
<script setup lang="ts">
import { z } from 'zod'
import type { FormSubmitEvent } from '#ui/types'

const schema = z.object({
  email: z.string().email('Format alamat email tidak valid'),
  password: z.string().min(8, 'Kata sandi wajib minimal 8 karakter')
})

type Schema = z.output<typeof schema>

const state = reactive({
  email: '',
  password: ''
})

const toast = useToast()

const onSubmit = async (event: FormSubmitEvent<Schema>) => {
  toast.add({
    title: 'Autentikasi Berhasil',
    description: `Sesi aktif untuk akun ${event.data.email}`,
    color: 'success',
    icon: 'i-lucide-check-circle'
  })
}
</script>

<template>
  <UCard class="max-w-md mx-auto my-12">
    <template #header>
      <h3 class="text-base font-semibold leading-6 text-gray-900 dark:text-white">
        Masuk ke Dashboard
      </h3>
    </template>

    <UForm :schema="schema" :state="state" class="space-y-4" @submit="onSubmit">
      <UFormField label="Alamat Email" name="email">
        <UInput
          v-model="state.email"
          placeholder="nama@perusahaan.com"
          icon="i-lucide-mail"
          class="w-full"
        />
      </UFormField>

      <UFormField label="Kata Sandi" name="password">
        <UInput
          v-model="state.password"
          type="password"
          placeholder="Minimal 8 karakter"
          icon="i-lucide-lock"
          class="w-full"
        />
      </UFormField>

      <UButton type="submit" block color="primary">
        Lanjutkan
      </UButton>
    </UForm>
  </UCard>
</template>
```

Perhatikan bagaimana komponen `<UFormField>` mencocokkan atribut `name` dengan kunci objek pada skema Zod. Ketika pengguna mengosongkan kolom atau salah mengetik format email, komponen langsung merender pesan kesalahan di bawah input beserta atribut `aria-invalid` untuk pembaca layar (*screen reader*). Saat validasi lolos, TypeScript menjamin keamanan tipe data pada objek `event.data`, sementara `useToast()` memunculkan notifikasi mengambang di sudut layar melalui konteks `<UApp>`.

## Optimasi Antarmuka Nuxt untuk Performa dan Skalabilitas

Merakit tampilan yang rapi hanyalah separuh pekerjaan. Separuh lainnya adalah memastikan antarmuka tersebut tetap gegas di perangkat pengguna dan mudah dipelihara saat skala aplikasi membesar. Berikut adalah tiga strategi arsitektur untuk menjaga performa dan skalabilitas proyek Anda.

### 1. Dampak Reka UI terhadap Skor INP (Core Web Vitals)

Banyak pengembang hanya terpaku pada kompresi gambar saat mengejar skor PageSpeed, tetapi melupakan metrik *Interaction to Next Paint* (INP). Pustaka UI generasi lama yang mengandalkan *runtime CSS-in-JS* sering memicu *Long Tasks* di *main thread* peramban setiap kali pengguna membuka modal, mengetik di kolom pencarian, atau mengubah filter tabel.

Kombinasi **Reka UI Nuxt** dan kompilasi statis **Tailwind CSS v4 Nuxt** menghilangkan beban tersebut. Reka UI hanya menyuntikkan logika perilaku dan aksesibilitas yang sangat ringan, sedangkan seluruh aturan gaya telah dikompilasi menjadi CSS statis saat proses *build*. Tidak ada kalkulasi gaya dinamis yang membebani CPU saat pengguna berinteraksi, sehingga respons visual tetap instan dan menjaga metrik Core Web Vitals aplikasi tetap hijau.

### 2. Skalabilitas Desain Perusahaan dengan Nuxt Layers

Jika Anda memimpin tim yang mengelola beberapa produk atau *micro-frontend* sekaligus, menyalin konfigurasi `app.config.ts` dan komponen kustom ke setiap repositori akan menyulitkan pemeliharaan.

Manfaatkan fitur **Nuxt Layers**. Nuxt UI secara otomatis menghasilkan direktif `@source` ketika dipadukan dengan Nuxt Layers. Dengan mekanisme ini, mesin Tailwind CSS v4 dapat memindai kelas utilitas lintas paket secara cerdas. Anda cukup membangun satu repositori *Design System Layer* terpusat yang menyimpan standar warna merek, tipografi, dan variasi tombol, lalu mewariskannya ke berbagai aplikasi Nuxt lain melalui properti `extends` di `nuxt.config.ts` tanpa risiko konflik gaya atau duplikasi konfigurasi.

### 3. Sinkronisasi State Tabel dengan Parameter URL

Saat membangun halaman *dashboard* menggunakan komponen `<UTable>` dan `<UPagination>`, hindari menyimpan *state* halaman aktif, urutan kolom, atau kata kunci pencarian hanya di dalam variabel `ref()` lokal. Jika pengguna memuat ulang peramban atau membagikan tautan kepada rekan kerjanya, seluruh posisi filter akan kembali ke pengaturan awal.

Padukan komponen tabel dan paginasi Nuxt UI dengan *composable* `useRouteQuery` dari VueUse. Dengan mengikat nomor halaman dan filter langsung ke parameter URL (seperti `?page=2&role=admin`), seluruh kondisi antarmuka tersimpan secara deklaratif di bilah alamat. Pendekatan ini membuat halaman data Anda mudah dibagikan (*bookmarkable*) serta siap dipadukan dengan strategi [pengelolaan Nuxt Content dan technical SEO](/id/blog/nuxt-content-dan-technical-seo) maupun pemanggilan data sisi server via [arsitektur backend dan integrasi modern Nuxt](/id/blog/arsitektur-backend-dan-integrasi-nuxt).

## Empat Kesalahan Umum Saat Menggunakan Nuxt UI

Dalam praktik pengembangan sehari-hari, ada empat kesalahan teknis yang paling sering menghambat produktivitas tim saat bermigrasi ke arsitektur Nuxt UI modern:

1. **Melewatkan Komponen `<UApp>` di `app.vue`**: Kesalahan ini menjadi penyebab utama gagalnya pemanggilan fungsi imperatif seperti `useToast()` dan sistem *overlay* modal. Tanpa pembungkus `<UApp>` di tingkat terluar aplikasi, konteks penyedia (*provider*) tidak terbentuk di pohon DOM dan memicu *runtime error*.
2. **Menimpa Style dengan `!important`**: Memaksakan kelas utilitas seperti `!bg-red-500` atau `!p-0` langsung pada atribut `class` komponen akan merusak urutan aturan *Tailwind Variants* dan membuat tampilan mode gelap berantakan. Selalu gunakan properti `:ui` lokal pada komponen atau ubah definisi *slot* di `app.config.ts`.
3. **Mendeklarasikan Ulang Modul Bawaan**: Menambahkan `@nuxtjs/color-mode` atau `@nuxt/icon` secara manual ke dalam array `modules` di `nuxt.config.ts` bersama `@nuxt/ui` justru mengacaukan urutan injeksi gaya. Biarkan Nuxt UI mengelola siklus hidup modul-modul pendukung tersebut.
4. **Mengabaikan Konfigurasi IntelliSense pada Proyek Baru**: Skema kustomisasi di dalam `defineAppConfig` dan properti `ui` tidak otomatis terbaca oleh pengaturan standar ekstensi Tailwind di editor kode. Pastikan tim Anda menyertakan konfigurasi `.vscode/settings.json` di repositori agar fitur pelengkapan otomatis kelas CSS tetap berfungsi.

::faq
  :::faq-item
  ---
  question: Apa perbedaan antara Nuxt UI dan Nuxt UI Pro?
  ---
  Nuxt UI adalah pustaka *open-source* gratis yang menyediakan lebih dari 50 komponen antarmuka fundamental seperti tombol, input form, *dropdown*, modal, dan tabel. Nuxt UI Pro adalah ekstensi berlisensi komersial yang menyediakan blok tata letak tingkat tinggi siap pakai, seperti kerangka *dashboard* admin, bagian *hero* halaman *landing*, template dokumentasi, dan tabel harga (*pricing table*).
  :::

  :::faq-item
  ---
  question: Bagaimana cara mengubah palet warna primer (Theming) di Nuxt UI?
  ---
  Anda dapat mengaturnya secara deklaratif melalui file `app.config.ts` tanpa perlu menulis variabel CSS manual. Cukup tetapkan nama token warna Tailwind pada objek konfigurasi, misalnya `ui: { colors: { primary: 'indigo', neutral: 'slate' } }`.
  :::

  :::faq-item
  ---
  question: Nuxt UI vs Shadcn Vue vs Vuetify, mana yang lebih tepat untuk proyek baru?
  ---
  Pilih Vuetify jika proyek Anda menuntut kepatuhan mutlak pada pedoman Material Design dan tidak mempermasalahkan ukuran *runtime* yang besar. Pilih Shadcn Vue jika Anda ingin menyalin seluruh kode sumber komponen ke repositori lokal dan siap merawatnya sendiri. Pilih Nuxt UI jika Anda menginginkan keseimbangan terbaik: manajemen dependensi yang bersih, integrasi Nuxt *native*, dan fleksibilitas kustomisasi Tailwind CSS v4.
  :::

  :::faq-item
  ---
  question: Apakah Nuxt UI bisa dipakai di proyek Vue 3 biasa tanpa Nuxt?
  ---
  Bisa. Mulai rilis Nuxt UI v3, pustaka ini mendukung penuh aplikasi Vue 3 berbasis Vite murni serta proyek *full-stack* yang menggunakan Inertia.js (seperti Laravel dan AdonisJS) tanpa ketergantungan pada server Nuxt.
  :::
