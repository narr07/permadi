**Vue Router** adalah pustaka perutean resmi ekosistem Vue.js yang memetakan URL peramban ke komponen antarmuka tanpa memicu muat ulang halaman penuh (*full page reload*). Pustaka ini mengandalkan HTML5 History API untuk mengelola perpindahan halaman secara instan di sisi klien, sehingga menjadi fondasi utama arsitektur *Single Page Application* (SPA).

Aplikasi web modern menuntut perpindahan antarmuka yang terasa secepat aplikasi desktop. Ketika pengguna mengeklik menu navigasi, peramban tidak perlu meminta dokumen HTML baru ke server dari awal. Sistem perutean mencegat perubahan URL, mencocokkannya dengan daftar rute yang terdaftar, lalu menukar komponen tampilan secara dinamis di layar.

Bagi Anda yang sedang mendalami [tutorial Vue JS modern](/id/blog/panduan-tutorial-vue-js), memahami mekanisme perutean adalah langkah wajib sebelum membangun aplikasi berskala produksi. Artikel ini membedah arsitektur dasar, pembaruan fitur generasi kelima, langkah instalasi dan konfigurasi proyek, hingga cara menangani jebakan reaktivitas yang sering menyulitkan developer di lapangan.

## Cara Kerja Navigasi SPA dan Komponen Inti

Secara tradisional, setiap tautan yang diklik pengguna memicu permintaan jaringan penuh ke server. Arsitektur SPA memutus siklus lambat tersebut dengan memindahkan logika pencocokan URL langsung ke peramban klien.

![Diagram alur navigasi aplikasi satu halaman membandingkan perutean peramban dan muat ulang server](/article/tech-vue-router-guide-ilustrasi.webp)

Sistem ini bekerja menggunakan tiga instrumen utama dari paket `vue-router`:

1. **`createRouter()` dan `createWebHistory()`**: Fungsi inisialisasi yang merakit instans router dan mengaktifkan pelacakan riwayat berbasis HTML5 (`pushState`, `replaceState`, dan *event* `popstate`).
2. **`<RouterView>`**: Komponen wadah (*slot* dinamis) yang diletakkan di templat utama. Komponen halaman yang cocok dengan jalur URL aktif akan dirender tepat di posisi elemen ini.
3. **`<RouterLink>`**: Komponen deklaratif pengganti tag `<a>` HTML standar. Elemen ini mencegah muat ulang halaman bawaan peramban sekaligus mengelola kelas CSS aktif secara otomatis.

Saat memilih mode riwayat perutean, Anda perlu menimbang karakteristik antara mode HTML5 dan mode Hash sesuai dengan lingkungan server tempat aplikasi akan dijalankan:

| Fitur & Karakteristik | `createWebHistory()` (HTML5 Mode) | `createWebHashHistory()` (Hash Mode) |
| :--- | :--- | :--- |
| **Bentuk URL** | Bersih dan standar (`permadi.dev/artikel`) | Menggunakan tanda pagar (`permadi.dev/#/artikel`) |
| **Mekanisme Dasar** | Memanfaatkan HTML5 History API (`pushState`) | Memantau perubahan karakter setelah simbol `#` |
| **Konfigurasi Server** | Wajib mengatur *fallback rewrite* ke `index.html` | Tidak perlu konfigurasi server khusus |
| **Kesesuaian SEO** | Sangat ramah mesin pencari dan analitik web | Kurang optimal untuk pengindeksan mesin pencari |
| **Skenario Ideal** | Aplikasi web produksi, portal publik, PWA | Aplikasi hibrida lokal (Cordova/Electron) atau *hosting* statis terbatas |

## Apa yang Baru di Vue Router 5?

Pada tahun 2026, pengelola utama Eduardo San Martin Morote (`@posva`) merilis **Vue Router 5**. Pembaruan besar ini menjawab dilema panjang di kalangan developer Vue: menulis daftar rute secara manual di dalam *array*, atau beralih menggunakan perutean berbasis struktur folder seperti saat kita [mengenal Nuxt JS](/id/blog/mengenal-nuxt-js-framework-vue-ssr-ssg).

Rilis versi kelima ini mengintegrasikan kemampuan `unplugin-vue-router` langsung ke dalam paket inti melalui sub-jalur `vue-router/vite` atau `vue-router/unplugin`. Developer aplikasi SPA murni kini dapat menggunakan perutean berbasis file (*file-based routing*) lengkap dengan dukungan *typed routes* dan parameter yang terverifikasi ketat oleh TypeScript tanpa menginstal dependensi pihak ketiga tambahan.

Kabar baiknya, rilis Vue Router 5 dirancang kompatibel ke belakang (*backward compatible*) tanpa merusak kode lama bagi pengguna versi 4. Jika proyek Anda masih menggunakan konfigurasi *array* rute statis tradisional, seluruh kode tetap berjalan mulus tanpa perlu ditulis ulang.

Selain penyatuan perutean berbasis file, versi 5 membawa dua lompatan teknis penting:

* **Data Loaders Eksperimental (`vue-router/experimental`)**: Fitur ini mengikat proses pengambilan data (*data fetching*) langsung ke siklus perutean sebelum komponen selesai dirender. Pendekatan ini memisahkan logika pemuatan data asinkron dari komponen UI, sejalan dengan pola loader modern seperti pada TanStack Router atau Remix.
* **Integrasi Native View Transitions API**: Anda kini dapat mengaitkan fungsi bawaan peramban `document.startViewTransition()` ke dalam *navigation guards* (`beforeEach` dan `afterEach`). Fitur ini menghasilkan animasi perubahan bentuk elemen (*morphing*) antarhalaman yang mulus tanpa membebani bundel aplikasi dengan pustaka animasi eksternal.

## Cara Install dan Konfigurasi Dasar Vue Router

Proses instalasi **Vue Router** pada proyek Vue 3 berbasis Vite dapat dijalankan langsung melalui terminal manajemen paket. Ikuti tahapan terstruktur berikut untuk menyiapkan arsitektur perutean yang siap pakai pada skala produksi.

::steps
### Instalasi Paket via Terminal
Jalankan perintah instalasi di direktori akar proyek Anda untuk mengunduh versi terbaru:

```bash
npm install vue-router@5
## Atau jika Anda menggunakan pnpm:
pnpm add vue-router@5
```

### Buat File Konfigurasi Router
Buat direktori dan file baru di `src/router/index.ts`. Di file ini, kita mendefinisikan peta jalur URL, pemuatan komponen bertahap (*lazy loading*), pengaturan posisi gulir layar, hingga halaman penampung 404.

```typescript
import { createRouter, createWebHistory } from 'vue-router'
import HomeView from '../views/HomeView.vue'

export const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/',
      name: 'home',
      component: HomeView
    },
    {
      path: '/tentang',
      name: 'about',
      // Lazy loading via Dynamic Import agar ukuran bundel awal tetap ringan
      component: () => import('../views/AboutView.vue')
    },
    {
      path: '/pengguna/:id',
      name: 'user-detail',
      component: () => import('../views/UserDetailView.vue')
    },
    // Rute Catch-all untuk menangani halaman 404 Not Found
    {
      path: '/:pathMatch(.*)*',
      name: 'not-found',
      component: () => import('../views/NotFoundView.vue')
    }
  ],
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) {
      return savedPosition
    }
    return { top: 0 }
  }
})
```

### Daftarkan Instans Router ke Aplikasi Utama
Buka file `src/main.ts` dan pasang instans router ke dalam aplikasi Vue sebelum memanggil metode `.mount()`.

```typescript
import { createApp } from 'vue'
import App from './App.vue'
import { router } from './router'

const app = createApp(App)

app.use(router)
app.mount('#app')
```

### Pasang Komponen Navigasi di Templat Utama
Buka `src/App.vue` dan tempatkan `<RouterLink>` sebagai menu navigasi serta `<RouterView>` sebagai kanvas render halaman.

```vue
<template>
  <header>
    <nav>
      <RouterLink to="/">Beranda</RouterLink>
      <RouterLink :to="{ name: 'about' }">Tentang Kami</RouterLink>
    </nav>
  </header>

  <main>
    <RouterView />
  </main>
</template>
```
::

Perhatikan properti `scrollBehavior` pada konfigurasi di atas. Michael Thiessen dalam bukunya *Nuxt Tips Collection* mengingatkan bahwa aplikasi SPA secara bawaan mempertahankan posisi gulir layar saat pengguna berpindah halaman. Mengembalikan objek `{ top: 0 }` memastikan layar otomatis bergulir kembali ke bagian paling atas layaknya situs web tradisional, sementara kondisi `savedPosition` menjaga posisi gulir tetap akurat saat pengguna menekan tombol *Back* di peramban.

Begitu pula dengan rute penampung `/:pathMatch(.*)*` di urutan paling bawah. Nail Titah dalam *The SEO Guide* menekankan pentingnya menangani tautan rusak (*broken links*) dengan menyediakan halaman 404 khusus. Membiarkan pengunjung melihat layar putih kosong akibat rute yang tidak terdaftar akan merusak pengalaman pengguna dan meningkatkan rasio pentalan (*bounce rate*).

## Pola Navigasi: Tombol Interaktif dan Pengalihan Rute

Dalam pengembangan antarmuka nyata, navigasi tidak selalu berbentuk teks tautan biasa. Desainer sering merancang tombol aksi (*call-to-action*) atau membutuhkan pengalihan otomatis setelah pengguna menyelesaikan sebuah tugas.

### Menangani Tombol Navigasi (Button Navigation)

Banyak developer pemula membuat kesalahan aksesibilitas saat merancang tombol navigasi di Vue Router. Mereka membungkus elemen `<button>` di dalam `<RouterLink>`, atau memasang event `@click="router.push('/tujuan')"` pada elemen `<div>` maupun tag `<a>` tanpa atribut `href`. Praktik tersebut merusak navigasi papan ketik (*keyboard navigation*), membingungkan perangkat pembaca layar (*screen reader*), dan mematikan fitur klik kanan atau klik tengah untuk membuka tab baru.

Terdapat dua cara bersih untuk menangani tombol navigasi berdasarkan konteks penggunaannya:

**1. Pendekatan Deklaratif Aksesibel (Slot `custom`)**
Jika tombol murni berfungsi memindahkan pengguna ke halaman lain, gunakan properti `custom` beserta `v-slot` pada `<RouterLink>`.

```vue
<template>
  <RouterLink to="/pembayaran" custom v-slot="{ navigate, isActive }">
    <button
      type="button"
      :class="['btn-utama', { 'btn-aktif': isActive }]"
      @click="navigate"
    >
      Lanjut ke Pembayaran
    </button>
  </RouterLink>
</template>
```

**2. Pendekatan Navigasi Programatik (Imperatif)**
Jika perpindahan halaman hanya boleh terjadi setelah proses asinkron selesai (seperti validasi formulir atau penyimpanan data ke API), gunakan *composable* `useRouter()`. Konsep ini serupa dengan fungsi pembantu `navigateTo` yang dijelaskan Michael Thiessen dalam *Nuxt Tips Collection* untuk menangani perpindahan rute di dalam kode skrip.

```vue
<script setup lang="ts">
import { useRouter } from 'vue-router'

const router = useRouter()

const simpanFormulir = async () => {
  const berhasil = await kirimDataKeServer()

  if (berhasil) {
    // Pindah ke rute bernama dengan membawa parameter ID
    router.push({ name: 'user-detail', params: { id: '402' } })
  }
}
</script>

<template>
  <button type="button" @click="simpanFormulir">
    Simpan & Lanjutkan
  </button>
</template>
```

### Mengatur Pengalihan Rute (Redirect vs Alias)

Perubahan struktur URL lama ke jalur baru menuntut pengaturan *redirect* yang tepat pada Vue Router. Anda dapat mendefinisikan pengalihan ini langsung di dalam tabel rute menggunakan *string* statis, objek rute bernama, atau fungsi dinamis yang mempertahankan *query parameter*.

```typescript
const routes = [
  // Redirect statis sederhana
  {
    path: '/profil-lama',
    redirect: '/akun/profil'
  },
  // Redirect dinamis yang mempertahankan query pencarian (?q=...)
  {
    path: '/cari-produk',
    redirect: to => {
      return { path: '/katalog', query: to.query }
    }
  }
]
```

Selain di level konfigurasi rute, pengalihan sering ditempatkan di dalam *Navigation Guards* (`beforeEach`) untuk mengamankan halaman khusus anggota atau panel admin:

```typescript
router.beforeEach((to, from) => {
  const sudahLogin = periksaTokenPengguna()

  if (to.meta.requiresAuth && !sudahLogin) {
    // Alihkan ke halaman login dan simpan URL tujuan awal di query
    return {
      name: 'login',
      query: { redirect: to.fullPath }
    }
  }
})
```

::note
**Pahami Perbedaan Redirect dan Alias:** Seperti yang dijabarkan Michael Thiessen dalam *Nuxt Tips Collection*, `redirect` akan mengganti URL di bilah alamat peramban ke URL tujuan baru. Sebaliknya, jika Anda ingin beberapa URL berbeda merender komponen halaman yang sama persis tanpa mengubah teks URL di peramban pengguna, gunakan properti `alias: '/jalur-alternatif'`.
::

## Jebakan Umum Vue Router dan Cara Menghindarinya

Meskipun API Vue Router terlihat lugas, ada tiga perangkap teknis yang kerap memicu *bug* tersembunyi di aplikasi produksi, terutama saat berurusan dengan sistem reaktivitas Vue 3 dan konfigurasi server.

### 1. Hilangnya Reaktivitas Saat Destrukturisasi `useRoute()`

Kesalahan yang paling sering muncul saat tinjauan kode (*code review*) adalah destrukturisasi objek `useRoute()` secara langsung di tingkat atas `<script setup>`.

```typescript
// SALAH: Nilai userId tidak akan diperbarui saat URL berubah dari /pengguna/1 ke /pengguna/2
const { params } = useRoute()
const userId = params.id
```

Objek yang dikembalikan oleh `useRoute()` adalah objek reaktif (*reactive proxy*). Destrukturisasi langsung akan memutus ikatan reaktivitasnya. Ketika pengguna berpindah dari `/pengguna/1` ke `/pengguna/2`, Vue menggunakan ulang instans komponen yang sama demi efisiensi performa, sehingga nilai `userId` tetap membeku di angka `1`.

Untuk mengatasinya, bungkus akses properti rute di dalam `computed()` atau gunakan pustaka `@vueuse/router` (`useRouteParams`):

```typescript
import { computed } from 'vue'
import { useRoute, useRouter } from 'vue-router'

const route = useRoute()
// BENAR: Reaktivitas terjaga penuh
const userId = computed(() => route.params.id)

// Alternatif menggunakan currentRoute yang merupakan shallowRef
const router = useRouter()
const jalurAktif = computed(() => router.currentRoute.value.path)
```

Dalam buku *Vue Tips Collection*, Michael Thiessen juga menyoroti bahwa `useRouter().currentRoute` sebenarnya adalah sebuah `shallowRef`. Memahami sifat referensi dangkal ini sangat penting ketika Anda membangun aplikasi berskala besar atau bekerja di lingkungan *Server-Side Rendering* (SSR) agar terhindar dari masalah *hydration mismatch* dan kebocoran status (*state leak*) antarpermintaan klien.

### 2. Error 404 dari Server Saat Refresh di Mode History

Ketika aplikasi dibangun untuk tahap produksi (*production build*) menggunakan `createWebHistory()`, navigasi dari halaman beranda ke `/tentang` berjalan normal karena ditangani oleh JavaScript di peramban. Namun, begitu pengguna menekan tombol *Refresh* (F5) saat berada di URL `/tentang`, peramban akan meminta file fisik `/tentang` langsung ke server web.

Karena aplikasi SPA hanya memiliki satu file fisik utama yakni `index.html`, server seperti Nginx atau Apache akan membalas dengan pesan kesalahan `404 Not Found`.

::warning
**Wajib Konfigurasi Server Fallback:** Saat men-deploy aplikasi SPA ke layanan *hosting* atau VPS, pastikan Anda menambahkan aturan *fallback rewrite* agar seluruh permintaan URL yang tidak merujuk pada file statis diarahkan kembali ke `index.html`. Jika Anda men-deploy aplikasi ke infrastruktur modern seperti yang dibahas pada [panduan Cloudflare Workers untuk backend serverless](/id/blog/arsitektur-cloudflare-workers-edge), aktifkan opsi *Single-Page Application (SPA) fallback* pada konfigurasi aset statisnya.
::

### 3. Mengabaikan Pemisahan Bundel (Lazy Loading)

Mengimpor seluruh komponen halaman secara statis di bagian atas file `router/index.ts` akan memaksa Vite menggabungkan semua halaman ke dalam satu file JavaScript berukuran besar. Akibatnya, waktu muat awal aplikasi melambat dan menurunkan skor performa web Anda.

Selalu gunakan sintaks impor dinamis `component: () => import('../views/NamaHalaman.vue')` untuk setiap rute sekunder. Vite secara otomatis memecah setiap halaman menjadi potongan file (*chunk*) terpisah yang hanya diunduh ketika pengguna mengunjungi rute tersebut. Praktik ini sangat efektif menjaga metrik pemuatan awal, sejalan dengan [panduan lengkap Core Web Vitals](/id/blog/panduan-optimasi-core-web-vitals) untuk memastikan antarmuka tetap responsif.

::faq
  :::faq-item
  ---
  question: Kapan harus menggunakan router.push() dibanding router.replace()?
  ---
  Gunakan `router.push()` untuk navigasi normal karena metode ini menambahkan entri baru ke tumpukan riwayat peramban, sehingga pengguna bisa menekan tombol *Back* untuk kembali. Gunakan `router.replace()` ketika Anda ingin menimpa entri riwayat saat ini tanpa menambah catatan baru, misalnya setelah pengguna berhasil login atau saat melakukan pengalihan halaman otorisasi agar pengguna tidak kembali ke halaman formulir login saat menekan tombol kembali.
  :::

  :::faq-item
  ---
  question: Apa perbedaan utama createWebHistory() dan createWebHashHistory()?
  ---
  `createWebHistory()` memanfaatkan HTML5 History API untuk menghasilkan URL standar yang bersih (seperti `domain.com/produk`), tetapi membutuhkan pengaturan *fallback* ke `index.html` di sisi server. Sebaliknya, `createWebHashHistory()` menyisipkan simbol pagar pada URL (`domain.com/#/produk`) yang langsung berfungsi di server statis mana pun tanpa konfigurasi tambahan, namun kurang baik untuk estetika tautan dan pengindeksan SEO.
  :::

  :::faq-item
  ---
  question: Apakah kode Vue Router 4 akan rusak jika di-upgrade ke Vue Router 5?
  ---
  Tidak. Vue Router 5 dirancang kompatibel ke belakang (*backward compatible*) untuk pengguna konfigurasi rute berbasis *array* dari versi 4. Pembaruan utama di versi 5 adalah penggabungan fitur *file-based routing* (`unplugin-vue-router`) langsung ke paket inti, verifikasi parameter dengan tipe data ketat, serta penambahan fitur eksperimental *Data Loaders*.
  :::

  :::faq-item
  ---
  question: Bagaimana cara mengamankan halaman admin di aplikasi SPA Vue?
  ---
  Tambahkan properti `meta: { requiresAuth: true }` pada objek rute halaman admin, lalu pasang *Global Navigation Guard* menggunakan `router.beforeEach()`. Di dalam fungsi tersebut, periksa status autentikasi pengguna dan kembalikan objek rute tujuan halaman login jika pengguna belum memiliki akses.
  :::
::

::conclusion
Menguasai **Vue Router** bukan sekadar menghafal cara memindahkan tampilan dari satu komponen ke komponen lain, melainkan merancang arsitektur navigasi yang aksesibel, cepat, dan tangguh di lingkungan produksi. Hadirnya **Vue Router 5** memberi Anda fleksibilitas penuh untuk memilih antara konfigurasi rute *array* klasik yang eksplisit atau perutean berbasis file modern dengan dukungan tipe data TypeScript yang ketat.

Sebagai langkah praktis berikutnya, audit kembali kode perutean di proyek Vue Anda saat ini:
1. Pastikan seluruh rute selain halaman beranda utama sudah menggunakan *lazy loading* (`() => import(...)`) untuk memangkas beban unduhan awal.
2. Ganti semua elemen `<button>` atau `<div>` yang memakai `@click="router.push"` pada tautan navigasi murni menjadi komponen `<RouterLink>` agar ramah aksesibilitas.
3. Tambahkan rute penampung `/:pathMatch(.*)*` beserta konfigurasi `scrollBehavior` untuk menjaga kenyamanan navigasi pengguna di segala kondisi.
::
